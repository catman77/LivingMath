# 005 — Причинное сопряжение native-модели с прогнозом проектов

**Дата:** 2026-11-01. **Состояние:** рабочее предложение, NO_REVIEW. Не отправлено.

## Основание

В пилоте [ROBLOX-PRED-001](../../roblox-pred-001/STAGE0_STAGE1_REPORT_RU.md) найден
реальный `SomaMarketAdapter`: рабочий файл соседнего SOMA
`soma_m0/src/soma_m0/core/adapter.py`, SHA256
`ef3dfc951acb4b18ef117cf45c073c34f7f181cb7632eca8ca87faa598f3f103`.
Операции predict_next/observe/probe_state существуют; kernel использует пять
числовых каналов. Подключённый LivingMath имеет source-oriented инструменты,
но готовый frozen Roblox structural extractor не выявлен.

## Что хотим улучшить

Нужна воспроизводимая связь между доступными на as_of наблюдениями проекта и
входами существующих native операций. Необходимы значение каждого канала,
квантование, порядок эпизодов, reset policy, probe schema и запрет чтения outcome.
Самописная эвристика под именем SUTI не решит эту задачу.

## Варианты решения

1. **Рекомендуемый первый эксперимент:** причинный поток разрешённых числовых
   наблюдений через существующий пятиканальный адаптер; native probe_state даёт
   признаки, одинаковый readout сравнивается с обычным ML. Kernel не меняется.
   Это проверяет структурную память числового процесса, но не понимание текста.
2. Отдельное source-bound отображение concept/text relations в native входы,
   если автор укажет реальные операции/инварианты. Нужны исходные адреса,
   witnesses и неизменяемые входные fixtures. Оно сложнее и проверяет другую
   гипотезу; нельзя смешивать его результат с вариантом1 без абляции.

Первый вариант минимален по реализации; второй имеет смысл только после
операционального определения отображения. Новых аксиом или DSL не предлагается.

## Связь с общим проектом

- **SUTI:** определить, какие имеющиеся операции действительно применимы к такому входу.
- **Bridge:** сохранить адреса/время/версии и проверяемое отображение каналов/отношений.
- **LivingMath:** зарегистрировать различимые гипотезы, одинаковые данные и отрицательные контроли.

## Проверка и текущее состояние

Сигнатуры и SHA исследованы read-only; kernel не запускался и не изменялся.
Есть только contract dry-run: features=null, UNSUPPORTED, без выдуманных результатов.
Данные пока BLOCKED по правам/истории. После gate заморозить mapping на train,
сравнить исходные/переставленные/случайные признаки на одном temporal split,
сохранить отрицательный результат и расход ресурсов. Выигрыш не предполагается.

## Вопрос автору и история обсуждения

Какое существующее операциональное отображение наблюдений проекта в native входы
сохраняет нужные различения и допускает проверку без доступа к будущему outcome?
Ответ автора на это предложение пока не получен. Предложение подготовлено локально;
оно не объявлено частью согласованной онтологии SUTI.
