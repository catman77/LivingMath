# 003 — Отдельные статусы и потеря различий в наблюдении

**Дата:** 2026-10-29. **Состояние:** проверено локально, готово к обсуждению;
авторский ответ `NO_REVIEW`. Материалы никому не отправлялись.

## Основание

Bridge003 исследовал два других реальных файла предоставленного автором
`SUTI.uni.zip`: `templates/learning-crystal.v1.schema.json` и
`SUTI.studium/schemas/study-session.v1.schema.json`. Точные SHA, цитаты и
byte/char offsets находятся в [пакете автору](materials/author-review-package.md)
и [адресах](materials/selected-fragments.json).

## Наблюдение

Полные схемы допускают пару записей с одинаковым `visibility=public`, но
разным `transfer_status`, и другую пару с `external_transfer=HOLD`, но
`decision=COMMIT/ROLLBACK`. Остальные обязательные поля сохранены.
Это модельные свидетели допустимости данных, не реальные учебные записи,
согласие на передачу или исполнение SUTI. Один показатель не восстанавливает
скрытое значение на этих парах.

## Варианты решения

1. **Сохранять отдельные поля при обмене — рекомендуемый текущий вариант.**
   Явно описать независимость наблюдений; схемы остаются исходными. Цена —
   несколько показателей вместо одного агрегированного статуса.
2. При наличии авторского замысла зависимостей добавить только подтверждённые
   условия совместимости значений. Цена — сужение области (`NARROWED`), версия
   и проверка уже существующих записей. Пока это только предложение.

## Связь с SUTI–Bridge–LivingMath

- **SUTI:** уточнить смысл сосуществования статусов и контракт обмена.
- **Bridge:** сохранять выбранные различия; отвергать скалярную трактовку
  как сохраняющую смысл, если она теряет обязательное поле.
- **LivingMath:** хранить исходник, конкурирующие трактовки, аудит и конечный
  контрпример в QA; не выводить разрешение из допустимости данных.

runtime остаётся `UNKNOWN`, исходные схемы не менялись. См.
