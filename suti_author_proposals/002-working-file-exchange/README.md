# 002 — Обмен рабочими материалами и обратным разбором

**Дата:** 2026-10-29. **Состояние:** рабочий вариант совместного порядка.
Файловый путь уже реализован в Bridge002; отдельный SUTI API не требуется.

## Основание и цель

Проекты находятся в разработке, исходники предоставлены автором в рабочих архивах.
На примере `SUTI.game/algorithm-contour.v1.md` уже выполнен цикл:
файл → различения → две модели → проверка → LivingMath QA → объяснение автору.

Предлагается закрепить удобный способ повторять такие циклы на следующих
материалах и возвращать автору понятные предложения вместе с их основаниями.
Начать можно с существующих файлов и обычного сообщения с вопросом.

## Варианты решения

| Вариант | Как работаем | Польза и издержки |
|---|---|---|
| **А. Исходный файл и сопровождающий разбор — рекомендуется сейчас** | Автор передаёт рабочий файл или архив и контекст; Bridge сам собирает хеш, адреса различений, модели и объяснение | Минимум дополнительной работы для автора; разметку Bridge нужно проверять по исходнику |
| **Б. Папка одного кейса** | Рядом лежат исходник, короткий файл вопроса/контекста, разбор и ответ автора; машинные метаданные при необходимости генерирует Bridge | Удобнее отслеживать несколько редакций и обсуждений; появляется небольшое соглашение об именах и структуре |

Для обоих вариантов исходный смысл не требуется заранее переписывать в JSON.
Хеши фиксируют конкретные рабочие байты и вычисляются автоматически. Если материал
обновился, Bridge показывает, какие различения и прежние выводы нужно перепроверить.
Неизвестное остаётся явно указанным; полнота формализации не предполагается заранее.

## Связь с SUTI–Bridge–LivingMath

- **SUTI:** предоставляет существующий материал, его контекст и при необходимости
  уточняет исходный смысл. Автор сохраняет возможность исправить вопрос и трактовку.
- **Bridge:** строит отображения с адресами источника, сравнивает содержательно
  разные модели, фиксирует потери и возвращает объяснение обычным языком.
- **LivingMath:** получает настоящие ссылки на источник и проверяемые вопросы;
  сохраняет свидетельства, контрпримеры и результаты аудита. Native-исполнение
  добавляется только для действительно подходящей реализации источника.

## Обратная связь автора

Достаточно обычного ответа по конкретному разбору: «узнаю смысл», «частично»
или «здесь подмена», с пояснением. В карточке сохраняются сам ответ, его источник
и дата; Bridge связывает его с рассмотренной редакцией файла и объяснения.
Если ответ передал пользователь, так и указывается. Подпись или машинный протокол
могут добавляться при практической необходимости, но не служат входным условием
локальной разработки.

## Что уже проверено и что дальше

Для первого реального файла проверены точные bytes и source spans, две модели,
обратное объяснение и read-only MCP-путь. Это ещё не испытание общего формата
на произвольных материалах и не сравнение качества с прямой LLM.

Практический следующий шаг: выбрать следующий содержательный рабочий материал
и повторить тот же цикл, сохранив его предложение в этом каталоге. Проверять,
сможет ли автор проследить вывод до исходного фрагмента и точно назвать подмену,
если она возникла.
