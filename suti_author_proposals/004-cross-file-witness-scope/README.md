# 004 — Межфайловые условия и область прежних свидетелей

## Основание

Bridge004 проверил точные пары Bridge003 по рабочим `SUTI.uni.zip` и
`SUTI.os.zip`: 3598 UTF-8 файлов, 27 241 580 байт, 1185 reference-кандидатов
и две отдельно отмеченные цитаты контекстного review. Полные исходные записи,
хеши и точные адреса — в [материале автору](materials/author-review-package.md).

## Наблюдение и смысловая граница

Пары `visibility=public` с разными `transfer_status` и
`external_transfer=HOLD` с `decision=COMMIT/ROLLBACK` проходят исходные схемы.
Дополнительного применимого исполнимого ограничения в измеренной области
не найдено. README студии отделяет решение о передаче от учебной пробы;
README академии называет публикацию отдельным решением. Привязка этих
текстов к точным полям, версии и этапу остаётся UNKNOWN.

Отсутствие условия в одной schema не означает независимость во всём SUTI.
Предыдущие свидетели сохранены, вывод расширен append-only ревизией;
текст не превратился в запрет или разрешение.

## Варианты решения

1. **Сохранять отдельные значения и неизвестность связи — текущий вариант.**
   Не добавлять в Bridge предполагаемые ограничения; предъявлять оба статуса
   и источник проверки. Схемы и старые записи остаются исходными.
2. Если автор укажет действительное условие, адресовать оригинал, установить
   область и проверить те же полные записи. При сужении обозначить NARROWED,
   версию и границу изменения. Одной текстовой рекомендации для автоматического
   запрета недостаточно.

## Связь с общим проектом

- **SUTI:** уточнить точную связь учебного решения, видимости и передачи.
- **Bridge:** проверять namespace/version/stage, различать текст, код и schema,
  сохранять исходный свидетель и условную новую ревизию.
- **LivingMath:** хранить обе формализации и источник, нормализовать и проводить
  аудит в QA без grants или математического verified.
