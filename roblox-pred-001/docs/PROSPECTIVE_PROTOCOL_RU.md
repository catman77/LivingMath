## Предпосылки запуска

1. Получить проверенное основание коммерческого ML-использования агрегированных
   данных и их сбора, включая права на версии текстов. API key сам по себе не
   снимает ограничения. Документ хранится приватно, его SHA фиксируется в registry.
2. До первого запроса зафиксировать рамку включения universe IDs, границы покрытия,
   creator/clone discipline и способ учёта неуспешных/закрытых проектов. Top charts
   не являются рынком в целом. Изменение рамки требует новой версии исследования.
3. Сохранить `data/input/prospective-frame.json`: `frame_id`, `frozen_at` (UTC),
   `universe_ids`; тот же набор IDs задать в конфиге. Source policy должна иметь
   реальное evidence/hash, EXPLICIT_EXCEPTION_OR_LICENSE, подтверждённые scope и
   `collection_allowed`. Это запись решения оператора, не автоматическая экспертиза прав.
4. После выполнения этих условий разрешить единственный capture-цикл. Никаких
   сервисов/таймеров этой реализацией не устанавливалось. Условная ежедневная
   команда: `python scripts/collect_snapshots.py --config configs/protocol.yaml`.
   Будущий внешний scheduler требует собственной операционной настройки.

## Временная шкала

Origin — дата первого разрешённого capture, сейчас не назначена. Pfirst означает
первое наблюдение нами, а не ранний релиз. Время получения фиксирует as_of; поздний
текст не переносится назад. Коллектор сохраняет raw response и SHA, записи и журнал
попыток. Пропавший из ответа ID остаётся UNAVAILABLE_UNKNOWN, не объявляется deleted.
429 останавливает цикл без retry; Retry-After записывается в причине. Сбой запроса
журналируется как censored attempt без фиктивных счётчиков; при построении outcome
он проявляется отсутствующим наблюдением.

Включение проектов распределяется заранее: train — дни [0,60), validation —
[151,181), test — [272,302). До начала следующей части предыдущие outcomes должны
уже быть доступны, включая время ingestion. Embargo — 91 день. Для последнего
проектного окна полное исследование займёт примерно **393 дня от origin**, а не
только 90. Cohort enrolment должна быть зафиксирована до соответствующего as_of.
Все проекты внутри заранее заданного frame сохраняются; selection по наблюдаемому
исходу запрещён. Creator/universe и известные clone groups не пересекают folds.
Конфликт останавливает оценку, а не молча удаляет проигравших.

Цель — 30 измерений в дни 61–90 около 18:00 UTC ±30 минут. Отсутствие любого дня
оставляет outcome=NULL. Такая консервативная версия A блокирует итоговую оценку
неполной cohort; нельзя выдавать complete-case estimate за исходную совокупность.
До реального запуска потребуется заранее выбрать содержательную обработку
censoring либо независимо валидируемое доснятие истории. Не менять правило после
просмотра test. Размеры не менее train200/validation100/test100 и не менее10
положительных train/test — минимальные технические gates, не расчёт мощности.

## Импорт разрешённой истории

`data/input/manifest.json`, формат `roblox-pred-import/1`:

```json
{
  "format": "roblox-pred-import/1",
  "source_id": "partner_licensed_export",
  "frame_id": "RIGHTS_CLEARED_FIXED_ENROLMENT_REQUIRED",
  "origin": "2025-01-01T18:00:00Z",
  "files": {
    "games": {"path": "data/input/games.jsonl", "sha256": "<sha256>"},
    "snapshots": {"path": "data/input/snapshots.jsonl", "sha256": "<sha256>"},
    "cohort": {"path": "data/input/cohort.json", "sha256": "<sha256>"}
  },
  "captures": {"<raw-sha256>": {"path": "data/raw/capture.json", "sha256": "<raw-sha256>"}}
}
```

Это шаблон, не существующий датасет. JSONL записи соответствуют Game/Snapshot;
для них также поддержан Parquet с полями моделей. `cohort.json` — полный список
`sample_id`, `universe_id`, `as_of`, `enrolled_at`, необязательных `clone_group_id`
и `clone_known_at`. source_license равна SHA документа разрешения; каждый hash
версии имеет реальный capture. Файлы и captures должны находиться внутри каталога
пилота. Истинность присланных нормализаций и документов не удостоверяется кодом:
оператор сохраняет процедуру экспорта, источниковые адреса и provenance.

Сначала `build_dataset`, затем `run_baseline`; реальные метрики открываются только
после freeze протокола/данных/кода/версий. `run_eval` читает тот же frozen результат,
не запускает повторный подбор на test. После data gate возможны этапы M2/S1/H1,
paired CI, калибровка и экономика; сейчас они не исполнялись.
