# Расширенная выборка для классификатора и SUTI–LivingMath

Собираем один быстрый срез: публичные чарты, остальные игры их создателей и
публичную жанровую выдачу. Длительного наблюдения и выручки не требуется.
Исходные50 топ-игр сохранены; новый набор добавляет малоактивные примеры.

## Что считать отрицательным примером

Основной быстрый тест — **текущая высокая/низкая аудитория**, правила
`configs/classifier-current-audience.yaml` зафиксированы до обучения этой версии:

- **1 /HIGH_ACTIVITY:** возраст universe от90дней, онлайн от1000.
- **0 /LOW_ACTIVITY:** возраст от90дней, онлайн до100 включительно.
- Внутри класса0 сохранён подтип: **32** игры с visits менее1млн и **220** с большим
  прошлым охватом. Последние не объявляются изначально провальными запусками.
- Молодые, промежуточные и недоступные проекты остаются в полном корпусе, без
  выдуманной метки. Для классификатора нужны creator и содержательное описание.

Итог:946 карточек;501 классифицируемый пример —249 положительных и252 отрицательных.
Train300 (149/151), validation100 (50/50), test101 (50/51). Дневное наблюдение не требуется.

Первая, более узкая версия `classifier-pilot.yaml` требовала онлайн до10,
visits до100000 и visits/возраст до100. Среди946 игр только15 имеют такую метку и
достаточное описание; в test было3 отрицательных. Её результаты сохранены в
`combined/prepared/`, но высокий AUC на таком test не используется как надёжный
результат. Все15 примеров отдельно экспортированы в `strict_low_traction_examples.csv`;
32 более широких малоохватных — в `low_reach_examples.csv`.

Метки являются **прокси активности**, а не финансовыми результатами. Дата создания —
прокси запуска; visits/возраст — грубый накопленный масштаб. V2 — исследовательское
уточнение задачи после анализа покрытия V1, а не независимая подтверждающая валидация.

## Обучение и проверка

Создатель и близкие описания объединены в компоненты: один creator, одинаковые
описания и char-ngram cosine от0.92 не пересекают train/validation/test.
Пять фиксированных stratified group folds: три train, один validation, один test.
Нормализация и TF-IDF обучаются только на train. Параметры фиксированы, test не
используется для подбора. Это быстрая поперечная проверка, не будущий launch forecast.

Контроли: train base-rate; logistic по возрасту/жанру/длине описания; TF-IDF текста
с теми же метаданными. Сохранены прогнозы, модели и измеренные метрики. Никакая из
этих моделей не названа SUTI. Для SUTI–LivingMath подготовлен **тот же** train и
слепой test; выводы о преимуществе системы требуют её реальных предсказаний.

`train_input.jsonl` содержит обучающие метки. `test_input.jsonl` и
`validation_input.jsonl` исключают аудиторию, visits, метку, creator, источник
попадания в выборку и URL/ID Roblox. Прямые рекламные счётчики в описаниях удалены
из model_description, исходные описания сохранены. Известность названий популярных
игр для предобученной LLM остаётся возможным смешивающим фактором.

## Команды

Из каталога пилота:

```bash
python scripts/collect_classifier.py
python scripts/enrich_classifier.py data/classifier/<run>
python scripts/prepare_classifier.py data/classifier/<run>/combined/current-audience
```

Выход `prepared/`: `all_games.csv`, `classifier_dataset.csv/json`,
`train_input.jsonl`, `validation_input.jsonl`, `test_input.jsonl`, отдельные labels,
`dormant_examples.csv`, `baseline-result.json`, `baseline-predictions.csv`.
Данные и модели остаются локально, вне Git. Collect поддерживает продолжение в
том же `--output`; он не повторяет уже завершённые портфолио. История ошибок
сохраняется.429/401/403 останавливают запуск; timeouts журналируются.

Чтобы сравнить SUTI–LivingMath или обычную LLM, зафиксировать JSONL с одним
`{"case_id":"case-00001","score":0.7}` на каждый test case, **затем** запустить:

```bash
python scripts/score_classifier.py --dataset data/classifier/<run>/combined/current-audience/prepared \
  --predictions /path/to/predictions.jsonl --model-name SUTI-LivingMath
```

Scorer отвергает пропущенные, посторонние/повторные case IDs и неверные scores;
сохраняет SHA прогнозов в выводе. Полный test input доступен модели, labels —
оценщику после фиксации прогнозов. Одно и то же правило применимо к контрольной LLM.

## Границы быстрого эксперимента

Поиск и видимые создатели не являются случайной выборкой всего Roblox. Недоступные
игры не превращены в отрицательные примеры. Модель измеряет различимость текущих
прокси-классов на этой выборке; accuracy не удостоверяет математическую истину,
физический эффект, финансовую состоятельность или будущий успех нового проекта.

## Измеренный результат и сбор

На отложенных101 играх balanced accuracy: base-rate50,0%; метаданные58,4%;
TF-IDF +метаданные61,4% (ROC-AUC0,681). Это контрольный baseline для дальнейшего
сравнения. Результата SUTI–LivingMath ещё нет: scorer и слепые входы подготовлены,
native классификатор не подменялся TF-IDF. Отсутствующее измерение не названо PASS.

Часть metadata batch была остановлена HTTP429. Новых запросов после этого не
делалось;500 карточек восстановлены из уже полученных raw responses. Их временная
метка — время сохранения файла, явно помеченное как approximate persistence time,
а не восстановленный HTTP Date.854 candidate IDs без полной карточки сохранены
как unresolved, не превращены в отрицательные игры. Исключение/порядок выдачи и
прерванная загрузка могут смещать выборку. API id=0 трактуется как unavailable,
а не игра с нулевой аудиторией. Исходные timeouts и binding error сохранены.

[Машиночитаемый итог](../reports/classifier-pilot.json) содержит пути, размеры,
метрики, SHA manifests и текущие ограничения. Результаты инженерных проверок и
исторические неудачи не переписывают друг друга.
