# SUTI–Bridge–LivingMath

Исследовательская система: исходный текст → формализация → условные модели →
свидетели и контрпримеры → сохраняемая история исследования. MCP-интерфейс
объединяет LivingMath, проверку исходных схем SUTI и алхимическую модель ALCH006.

Текущий продукт: **`v0.4.11-developer-preview`**: assurance CLI, Semantic Bridge, численная White Star и Symbolic V1; 94 MCP-инструмента (93 прежних + frozen redecode). [Установка](README_QUICKSTART_RU.md), [White Star и сравнение режимов](docs/white-star/QUICKSTART_RU.md), [Semantic Bridge](docs/semantic-bridge/QUICKSTART_RU.md), [CLI](CLI_REFERENCE.md), [границы возможностей](LIMITATIONS.md).

декодирования одного сохранённого ответа без нового модельного вызова. Старые
93 схемы и вычислительные ядра сохранены. [Точный запрос](docs/nl-causal003/QUICKSTART_RU.md),
[эксперимент и ограничения](docs/nl-causal003/USER_REPORT_RU.md).

**NLProposalBridge/1 (0.4.10)** добавляет opt-in source-bound NL proposals,
проверяемое происхождение White Star, общий типизированный AST move и replay
замороженного provider receipt. Импортный `formal_interpret` сохранён как путь
деклараций. Гипотезы остаются `PROPOSED`; происхождение и типы не доказывают смысл.
[Запросы и rights](docs/nl-proposer002/QUICKSTART_RU.md),
[архитектура адаптера](docs/nl-proposer002/ARCHITECTURE_RU.md),
[приёмка и границы](docs/nl-proposer002/IMPLEMENTATION_REPORT_RU.md).
[Опубликованный release и полный пакет](docs/nl-proposer002/DELIVERY_RU.md).


**Formal Bridge v1 (0.4.9)** добавляет ограниченный поиск CFG/DFA из train,
packed forests с независимой проверкой, различающие запросы и отдельные
source-bound типизированные FOL proposals. Проверены два типа пар, палиндромы,
автомат чётности и активное уточнение `(ab)+`; разные трактовки и деревья сохраняются.
Три предложенных чтения одной фразы дают различные следствия в конечных моделях.
[Результаты и точные границы](docs/formal-bridge001/IMPLEMENTATION_REPORT_RU.md),
[MCP-контракт и примеры](docs/formal-bridge001/QUICKSTART_RU.md).
Человеческие FOL-аннотации остаются `PROPOSED`; автоматический общий NL→FOL
декодер не заявлен. `UNIVERSAL_INVARIANT=false`.

White Star использует предоставленное неизменённое ядро Белая звезда → CAD → Удав. Один frozen semantic snapshot можно передать ему и действующему Bridge/assurance без повторного extraction. Численные предложения и сохранённые LLM-прочтения разделены; native SUTI не исполняется. [Отчёт, фактическое сравнение и приёмка](docs/white-star/USER_REPORT_RU.md).

Symbolic V1 сохраняет полные токенные истории, UTF-8 spans и DAG операций. Это конечные структурные эксперименты, не доказательство найденной семантики. [Запуск и точный пример MCP](docs/symbolic-v1/QUICKSTART_RU.md), [измерения и ограничения](docs/symbolic-v1/IMPLEMENTATION_REPORT_RU.md). PATCH001 добавляет композиционные гипотезы, явный UNDERDETERMINED/active probe, локальный saturation certificate и comparison-view. [Приёмка PATCH001](docs/symbolic-v1/patch001/PATCH001_IMPLEMENTATION_RU.md).

PATCH002 добавляет ограниченный детерминированный переход к сохранённому фронтиру после локальной стагнации. На том же запросе Нострадамуса: 383 узла / 99 шагов вместо 18 / 5, в прежних бюджетах; это охват структур, не свидетельство найденного смысла. Грамматическая модель и 75 MCP-схем сохранены. [Отчёт PATCH002](docs/symbolic-v1/patch002/USER_REPORT_RU.md), [RCA и воспроизведение](docs/symbolic-v1/patch002/PATCH002_IMPLEMENTATION_RU.md).

PATCH003 добавляет конечные SP 2-комплексы с независимой проверкой путевой согласованности, аудит происхождения наблюдателей и слепое сравнение на 942 французских катренах. Положительная инженерная приёмка не означает положительного переноса: global-alpha модель не улучшила baseline; пунктуационный контроль оказался сильнее. Приёмочный follow-up исправляет предпосылки частичных SP-комплексов и демонстрирует реально используемый operator-derived observer на фиксированной задаче:256/256 heldout против128/256 при его отключении. Это конечная композиция существующего AST, не универсальный invariant. Полная иерархия всех942 катренов проверена отдельным source-bound harness. FIX-B2 соединяет размеченные операторные контексты с promotion в first-class feature registry. На исходном contains-SP контроле новый независимо проверенный предиктор дал 16/16 и 32/32 на новых словах длины 5; parent ablation даёт 5/16 и 6/32. PATCH004 превращает типизированные рекурсивные композиции существующих SPLIT/REVERSE и равенства слов в независимо проверяемые наблюдатели. На закрытых PAL/COPY задачах — 64/64 и 256/256; модель заморожена до queries, builtins отключены. Новый путь включается явно через `promotion_policy`; прежний literal-context default сохранён. Это ограниченное вычисление, не универсальная грамматика и не подтверждение смысла произвольного текста. ## Установка и первый запуск

Для актуального пакета нужны Python 3.13+ и Git. Для изолированных White Star
workers дополнительно нужны Linux x86_64 с Landlock ABI≥3 и C++17.
Из корня репозитория:

```bash
git clone https://github.com/catman77/LivingMath.git
cd LivingMath
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install '.[white-star,mcp,test]'
lm-suti doctor --smoke
lm-suti white-star prepare
python -m pytest -q tests
```

Это установка текущего кода и локальная проверка; HTTP автоматически не запускается.
Действующий полный сервер запускается через `tools/release_v01_entry.py` с
приватной owner-конфигурацией и публикует **91** инструмент. Отдельный
`unified_system.local prepare/serve/smoke` создаёт новый legacy стенд с **44**
инструментами; он не является установщиком полного production release.

Подробно: [установка, запуск и подключение ChatGPT](docs/INSTALL.md),
[использование и точные JSON-запросы](docs/USAGE.md), [тестирование](docs/TESTING.md).
Исторический отказ запуска GitHub Actions от 2026-11-01 и его RCA сохранены
в [CI_STATUS.md](docs/CI_STATUS.md); актуальный CI оценивается по run конкретного commit.
Для LLM-формализации требуется отдельно включить существующий Codex backend;
инструкции описывают вход через ChatGPT без API-ключа.

## Что предлагаем автору SUTI

В [отдельной папке предложений](suti_author_proposals/README.md) собраны изменения
и уточнения, которые **мы предлагаем добавить или обсудить в SUTI**:

1. Уточнить лимит меню: считать действия отдельно от `pause/skip/exit`.
2. Согласовать обмен рабочими файлами и обратным разбором.
3. Сохранять разные оси статусов и уточнить возможные зависимости.
4. Установить область применимости межфайловых условий и свидетелей.
5. Согласовать проверяемое сопряжение native SOMA/SUTI с прогнозом аудитории проектов.

Каждая карточка содержит основание, варианты решения и проверку. Это наши
предложения, а не принятые автором изменения или официальная реализация SUTI.
Ответ автора по этим карточкам пока не зафиксирован. Исходный runtime SUTI
здесь не исполняется; проверяются опубликованные схемы и условные модели.

## Известный результат Meaning014

На 24 новых открытых фрагментах C сформировал 8 различающих вопросов;
равно информированный B+ получил те же 8. Научный итог —
**`FAIL_NO_GAIN_OVER_B_PLUS`**. Рекомендован основной путь B/B+;
C остаётся экспериментальным. Независимой человеческой разметки нет,
семантическая accuracy и noninferiority не установлены. Три контрольных
случая закончились `COST_BOUND`; отсутствующие ответы не подменены.

Конечное доказательство относится к заявленной модели и предпосылкам.
`COMPLETED` означает завершение workflow; оно не присваивает `verified`,
не удостоверяет смысл исходника и не даёт разрешения на физическое исполнение.
Подробнее: [исследовательский статус](docs/RESEARCH_STATUS.md),
[полный отчёт](meaning_pivot014/USER_MODEL_REPORT.md), [RCA](meaning_pivot014/RCA.md).

Правила участия: [CONTRIBUTING.md](CONTRIBUTING.md).

## Коммерческий пилот Roblox

[ROBLOX-PRED-001](roblox-pred-001/README_RU.md) содержит самостоятельный Python-пакет,
семь таблиц Parquet/DuckDB, защиту от future leakage, временные splits и M0/M1.
Расширенная выборка содержит946 игр из чартов, публичных портфолио и жанрового
поиска. Для классификатора подготовлен501 пример:249 с высокой аудиторией и252
с низкой; train/validation/test300/100/101 разделены по создателям и близким
описаниям. Слабые метки активности не объявлены финансовыми исходами.
TF-IDF baseline: balanced accuracy61,4% на101 тестовой игре. Для SUTI–LivingMath
подготовлен тот же слепой тест; его результат ещё не измерен.
[Данные, подтипы отрицательных примеров и команды](roblox-pred-001/docs/CLASSIFIER_PILOT_RU.md).
Ежедневный сбор отключён; накопление90-дневной истории для быстрого теста не требуется.
