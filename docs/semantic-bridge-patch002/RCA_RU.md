# RCA — Semantic Bridge PATCH002

## Подтверждённая исходная причина

Шесть contextual-файлов фактического runtime v0.4.14 совпали с Git blob SHA из приложенного `BASELINE.json`. В `relations.pair` доказатель принимает только `forall`; валидное существовательное удаление конъюнкта остаётся без сертификата. Затем `fol.countermodels` последовательно получает почти весь остаток бюджета на A⇒B и снова начинает с первой модели на B⇒A. `engine.analyze` также последовательно обрабатывает пары. Невозможный контрпример отнимает бюджет у доступного; общий CHECKED скрывает незакрытые направления.

Исправление: сертифицируемая монотонность одинаковых смешанных префиксов и узкая ННФ, затем единый детерминированный поток закрытых конечных миров. Каждый мир проверяется для всех активных пар и обеих направленностей при общих предпосылках соответствующей пары. Размеры, relation cells и глобальный бюджет не увеличиваются. Непроверенное направление остаётся открытым; ранее найденные доказательства и контрмодели сохраняются.

## Семантическая причина

T4 смешивал содержание сообщения с истинностью сообщённого. FOL проверяет переданный AST и не лицензирует его соответствие русскому источнику. Это исправляется клиентским протоколом: альтернативы референта, factivity risk, source links, различающий сценарий и OPEN obligations. Имя предиката MessageEngineerWrong не доказывает адекватность интерпретации. T6 требует порядка событий; статическая конъюнкция его не выражает. Сервер не получает словарь речевых актов, скрытую LLM или semantic scorer.

## Границы поставки

PROVED относится только к проверенному классу формальных отношений. FINITE_CHECKED относится только к явно закрытой конечной модели. UNKNOWN не означает опровержение. SEMANTIC_PROPOSED и NOT_EVALUATED сохраняются; причинный LLM uplift не измерен. Старые immutable runs не пересчитываются задним числом; replay требует точного binding.

## Особенности исходного пакета и операторские ошибки

- В промпте указан `reference/REPORT_RU.md`; фактически пакет содержит `reference/EXP02_REPORT_RU.md`, прочитан именно он. Пакет не исправлялся.
- API отключения GitHub Actions успешно вернул HTTP204 без тела. Старый операторский JSON-helper ошибочно пытался разобрать пустое тело; helper исправлен, последующий GET подтвердил enabled=false. Повторная мутация не выполнялась. Эта ошибка не затрагивала MCP или данные.
- Первый интеграционный запуск в новом worktree дал 12 ошибок ENGINE_UNAVAILABLE_NATIVE_NOT_PREPARED: нативная библиотека ещё не была собрана для этого дерева. Выполнена штатная `white-star prepare`; SHA нативной библиотеки совпал с baseline. Повтор: 47 PASS, защитные проверки не менялись.
- В расширенном тесте тяжёлой пары агент первоначально заменил виды кванторов, не переставив связывания: получились несравнимые ∀e∃a и ∃e∀a, оба контрпримера нашлись за 14 моделей. Неверно ожидался незакрытый остаток. Тест исправлен на требуемые ∀e∃a и ∃a∀e; исходные 2 FAIL сохранены в UNIT_EXTENDED.log. Утверждения приёмки не ослаблялись.

Дальнейшие результаты и обнаруженные регрессии фиксируются по мере реального исполнения; исходные отчёты EXP02 остаются неизменными.

## Дополнительный дефект, обнаруженный независимым ревью

Разделение моделей не обеспечивало разделение вычислительного топлива: валидная формула с 14 кванторами могла израсходовать оставшийся max_steps при вычислении одной модели, и общая обработка прекращалась на пятом мире. Дешёвый T3-контрпример, доступный на мире №11, не доходил до проверки. Исходная критическая находка и воспроизводимый probe сохранены в math-review.md/math-checks.json.

Исправление дополняет общий курсор независимыми квотами шагов/CPU для каждой пары (proof + search), оплачиваемыми из прежнего общего бюджета. При локальном исчерпании только эта пара остаётся UNKNOWN_BOUND; другие продолжают. Для сценарных проверок резервируется часть общего топлива. UNKNOWN_BOUND не выдаётся за FINITE_EXHAUSTED. Счётчик миров увеличивается при фактическом обращении к FOL evaluation или проверенному кэшу мира, а не при создании непроверенного объекта модели. Глобальные max_models/max_steps/max_cpu_ms и worker-ограничения не увеличены.

Первоначальная попытка сборки через production-venv не нашла setuptools.build_meta: runtime-окружение намеренно не содержит build toolchain. Production-venv не изменялся; wheel собран локальным Python с уже установленным setuptools 80.9.0/wheel 0.45.1, затем установлен в новое чистое окружение. Исходный журнал WHEEL_BUILD.log сохранён.

## Production: отказ owner-only файла и фактический rollback

Первая попытка переключения отказала на load_private: release.private.json имел0644, поскольку первичный baseline-helper создал файл до установки umask077. Перезапись содержимого не меняет существующий mode. HTTP автоматически восстановлен прежним drop-in; исходный pointer не изменялся, текущий drop-in сверился byte-exact с backup. Исходный snapshot и DEPLOY.log сохранены.

Исправление операторского процесса: chmod0600 для реальной owner config, дополнительный preflight load_private для release/authorization/legacy config **перед остановкой HTTP**, отдельный backup-cutover-final и повторная установка. Guard/bootstrap не ослаблялся, исходники математического слоя не менялись. Вторая установка прошла236+68 публичных MCP проверок. URL и tunnel PID1474115 сохранены. Эта ошибка не скрыта за итоговым инженерным PASS.

## Документация: выбор реального принятого replay-примера

Начальный генератор выбирал первый transcript entry по имени инструмента. Для semantic_bridge_replay первым шёл намеренный отказ KERNEL_BINDING_UNAVAILABLE на историческом binding; он ошибочно попал в accepted_response. Документационное ревью обнаружило это до публикации. Выбор исправлен на фактический isError=false/ok=true/REPLAY_MATCH текущего QA-проекта. Все5 примеров сверены с реальными принятыми запросами; исходный ошибочный example и все отрицательные исторические транскрипты сохранены. Материалы исследований и production не менялись.
