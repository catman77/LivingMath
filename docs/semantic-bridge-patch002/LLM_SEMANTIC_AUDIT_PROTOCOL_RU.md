# LLM semantic audit — клиентский протокол для PATCH002

**Статус:** спецификация клиентского поведения, не доказанный алгоритм понимания естественного языка. Серверная логика не должна притворяться семантическим оракулом.

## Два этапа

**До `semantic_bridge_register`.** LLM читает буквальный текст и контекст, указывает source spans, формулирует не меньше одной возможной интерпретации и альтернативы, если двусмысленность реальна. Для каждого кандидата создаёт FOL AST, сортированную сигнатуру, `assumptions`, `obligations: OPEN`, construction trace и отдельный self-audit. Нельзя автоматически приписывать факт, только потому что текст сообщает о факте. Отдельно анализировать: `factivity_leak`, `source_entailment`, `scope`, `negation`, `anaphora`, `presupposition`, `temporality`, `expressivity_gap`. Не заменять отсутствующие операции языка псевдопредикатом, который маскирует потерю смысла.

**После `semantic_bridge_analyze`.** Проверить доказательные сертификаты и контрмодели. Сопоставить их с тем, что *действительно утверждал исходный текст*. Обновить только собственные гипотезы новым `request_key`/batch, сохранить lineage предыдущего draft. При неизвестном авторском намерении воздержаться от выбора; при недостатке FOL выдать `LANGUAGE_INSUFFICIENT`, даже если статический прокси типизирован.

## Обязательные тесты самокритики

1. «Инженер сообщил аналитику, что он ошибся»: `Said(e,a)∧WrongEngineer(e)` потенциально неверно приписывает фактическую ошибку. Отдельное `MessageEngineerWrong(e,a)` обозначает *содержание сообщения*, и тоже остаётся PROPOSED. Местоимение «он» допускает разные референты — `ANAPHORA:OPEN`.
2. «Полагает, что P», «ожидает P», «сообщил, что P»: не делать вывод P без отдельного текстового или внешнего основания.
3. «Не все статьи...» нельзя подменять «Ни одна статья...»; проверять области отрицания.
4. «После проверки гипотеза стала общепринятой»: `Checked(h)∧Accepted(h)` не кодирует предшествование, `TEMPORALITY:OPEN` и/или unsupported.
5. «Своему руководителю»: existence/uniqueness не следует автоматически из истинности импликации о потенциальных руководителях; проверить отдельную presupposition.

## Что сохраняет сервер

- Фактическое происхождение source/AST/model/вычислений и локальную формальную истинность.
- Различия между candidate AST, направленные доказательства, честные неизвестные отношения.
- OPEN obligations и запрет автоматически делать их RESOLVED.

Он **не** проверяет: соответствует ли предложенное значение `MessageEngineerWrong` реальной русской семантике, намерению говорящего или доступному миру. Проверка семантического uplift требует отдельного слепого A/B с экспертной разметкой.

## Точный действующий контракт и различающий сценарий

Новые поля MCP не нужны. Риск фактивности записывается как `obligations` с `kind="LEXICAL_ASSUMPTION"` или `"CONTEXT"`, `status="OPEN"`; маркер `RISK_FACTIVITY_LEAK` и описание различающего мира помещаются в `description`. `ANAPHORA` и `TEMPORALITY` уже поддерживаются. Буквальный текст и точные UTF-8 byte spans помещаются в `source_links`; AST-путь указывается лишь к реально существующему узлу. `construction_trace[].note` сохраняет самоаудит клиента. Произвольный `semantic_risk_ledger`, новые значения kind и поля scenario добавлять в запрос нельзя.

Например, объект обязательства для T4: `{"id":"factivity","kind":"LEXICAL_ASSUMPTION","status":"OPEN","description":"RISK_FACTIVITY_LEAK: различающий мир — сообщение об ошибке есть, фактической ошибки нет; сообщение не лицензирует WrongEngineer."}`. Отдельное обязательство `{"id":"referent","kind":"ANAPHORA","status":"OPEN","description":"Он: инженер или аналитик; отдельные MessageEngineerWrong/MessageAnalystWrong, авторский референт не установлен."}`. Добавьте реальные source_links к зарегистрированному источнику. Модель мира передавайте через formal_store и существующий model_refs, а не как новое поле register.

После расчёта сохраняйте отдельную клиентскую запись: буквальный источник/хеш → исходный draft/хеш → формальный run и направленное свидетельство → новый draft → происхождение пересмотра (`SELF_AUDIT` или конкретное свидетельство MCP) → остающиеся OPEN. Без слепого контроля эта запись не доказывает causal uplift. Протокол слепого исследования сохранён в `../SEMANTIC_BRIDGE_PATCH002_20261109/reference/NEXT_AB_PROTOCOL_RU.md`; в этой инженерной поставке он не исполнялся.
