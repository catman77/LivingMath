# Теоретическое ядро: множество формальных интерпретаций

## 1. Исходная постановка

Формализация естественной фразы — это **недоопределённая обратная задача**, а не единственная функция перевода текста в «истинный смысл». Проекция человеческого высказывания в логический/операционный мир требует выбора домена, ролей, области действия кванторов, временного контекста и часто нескольких дополнительных аксиом.

Предлагаем конструкцию `Interpretation`:

\[
I=(X,\Sigma,\varphi,\Gamma,\pi,\rho,\mathcal W,\sigma).
\]

Где `X` — исходный текст с SHA-256 и байтовыми отрезками, `Σ` — типизированная сигнатура, `φ` — формальный терм (формула, грамматика, переписывание, автомат или вычислительная спецификация), `Γ` — дополнительные предпосылки, `π` — трасса синтаксического/морфологического/контекстного происхождения, `ρ` — конкретная программа построения, `W` — проверяемые свидетельства, `σ` — эпистемический статус.

Разные `I_j` могут иметь одинаковое денотационное множество моделей, но разные структуры вывода; «одна формула» не стирает provenance.

Для текста `x` возвращается **не множество истины**, а конечное на текущем бюджете семейство предложений:

\[
\mathcal I_B(x)=\{I_1,\ldots,I_k\}\qquad(k\le B),
\]

с указанием, почему остановился поиск, какие формы не покрыты и какие варианты отвергнуты типизацией. Возможные интерпретации могут быть бесконечны; конечная выдача не является полным перечислением.

## 2. Проверка каждого слоя

**Грамматика.** Явное дерево вывода `T` является доказательством принадлежности `w∈L(G)` только когда независимый verifier проверяет start-symbol, production ID, terminal tokens, spans, source hash и локальную композицию. Без дерева `accepted=True` — лишь предсказание. Положительный witness проверяем; отрицание принадлежности требует либо завершённого алгоритма, либо честного `UNKNOWN` при ограничении бюджета.

**Семантика.** Для корректно типизированной FOL-формулы и заданной конечной модели `M` истинность `M⊨φ` вычислима точно. Но из `M⊨φ` не следует, что `φ` является правильной трактовкой исходной русской фразы.

**Взаимосвязь интерпретаций.** Внутри объявленного класса моделей `K`:

\[
I_i\models_{K} I_j\iff\forall M\in K:\;M\models(\Gamma_i\wedge\varphi_i)\Rightarrow M\models(\Gamma_j\wedge\varphi_j).
\]

Это определение entailment, не процедура принятия решения для неограниченного FOL. Контрмодель `M` с противоположной истинностью — строгое свидетельство неэквивалентности. Если конечный перебор ничего не нашёл, результат — `NO_COUNTERMODEL_WITHIN_BOUND`, а не `EQUIVALENT`.

**Различимость.** Для фиксированных кандидатов пусть

\[
\Delta_{ij}=\{M\in K\mid (M\models\varphi_i)\oplus(M\models\varphi_j)\}.
\]

Контроль выбирает недорогой `M∈Δ_ij` с предъявляемым разбором разногласия. Для языков тот же принцип:

\[
\Delta(G_i,G_j)=L(G_i)\triangle L(G_j).
\]

На конечном домене/длине это можно вычислить и дать различающее слово; отсутствие различающего слова на `|w|≤N` **не доказывает** эквивалентность двух произвольных КС-грамматик (эквивалентность CFG в общем случае неразрешима).

## 3. Три чтения и конечные контрмодели

Текст: «Каждый исследователь проверил одну гипотезу».

Сигнатура: сорта `Researcher`, `Hypothesis`; бинарный предикат `Checked: Researcher×Hypothesis→Bool`.

- `I1`: `∀r ∃h Checked(r,h)` — у каждого хотя бы одна;
- `I2`: `∃h ∀r Checked(r,h)` — одна общая для всех;
- `I3`: `∀r ∃h (Checked(r,h) ∧ ∀h' (Checked(r,h')⇒h'=h))` — у каждого ровно одна.

Для `r1→h1, r2→h2`: `I1=T, I2=F, I3=T`. Для `r1→h1,h2; r2→h1`: `I1=T, I2=T, I3=F`. Эти контрмодели проверены в `src/run_acceptance.py`.

Условия важны: два сорта непусты, а `Checked` имеет **замкнутый мир только в этих тестовых моделях**; отсутствие записи не означает ложь в произвольной реальной базе. Референсная конструкция формул для этого примера написана вручную; она является проверяемым приёмочным oracle для будущего генератора, не существующим NLP-компонентом MCP.

## 4. Белая звезда и роли модулей

Предлагаемый стек:

```text
Текст + контекст + provenance
    ↓
White Star symbolic exploration → кандидаты различений, группировок и деревьев
    ↓
[НОВЫЙ] Grammar Discovery → проверяемые CFG/DFA гипотезы
    ↓
[НОВЫЙ] Typed Interpretation Proposer (внешний/LLM-контур при наличии)
    ↓
[НОВЫЙ] Elaborator/Type Checker → Σ, φ, Γ + точные исходные spans
    ↓
Independent Proof/Model Checker → проверенные/опровергнутые экземпляры
    ↓
Contrastive Model Search → вопросы/контрмодели/различающие слова
    ↓
Archive: candidate graph, hypotheses, counterexamples, bounded UNKNOWN
```

Не подменять звенья. Текущий серверный `white_star_symbolic_explore` работает с исходными токенами и операторами; он НЕ выдаёт самостоятельно типизированную FOL-семантику. `SUTI_native_runtime` согласно текущему статусу не исполняется. Новый NLP-конструктор разрешено строить отдельно, но нельзя выдавать внешнюю LLM-аннотацию за доказательство.

**Семантическое несхлопывание:** сохранять (а) различные источниковые интерпретации, (б) их типизированные формулы, (в) доступные модели, (г) разные деревья одной грамматики, (д) минимальные counterexamples. Функциональная эквивалентность результата на конечном тесте не уничтожает различий в дереве и происхождении.

## 5. Статусы и запрет семантического допинга

Для grammar discovery: `TRAIN_COMPATIBLE`, `HOLDOUT_PASS`, `HOLDOUT_FAIL`, `VERIFIED_DERIVATION`, `NO_COMPATIBLE_IN_DECLARED_CATALOG`, `UNKNOWN_BUDGET`.

Для интерпретаций: `PROPOSED`, `TYPED`, `TYPE_REJECTED`, `COUNTERMODEL_FOUND`, `FINITE_MODEL_CHECKED`, `UNDERDETERMINED`, `HUMAN_ADJUDICATED` (только с человеком), `FORMAL_PROOF_VERIFIED` (только с настоящим доказательством).

Никогда не использовать один статус `VERIFIED`, обозначающий одновременно «правильно извлечено из текста», «формула типизирована», «модель её удовлетворяет» и «теорема доказана». Это четыре разных утверждения.
