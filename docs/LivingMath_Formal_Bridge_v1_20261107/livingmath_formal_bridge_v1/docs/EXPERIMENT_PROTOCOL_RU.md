# Экспериментальная программа: сначала формальные языки, потом controlled NL

## Сравнение с предыдущей приёмкой

Старый MCP v0.4.8: Dyck(1) 764/764 на конечных holdout; `a^n b^n` 256/256 на НЕПУСТОМ контроле; дополнительное `ε` опровергло правильность найденной nullable-грамматики для n≥1. Dyck(2) и чётные палиндромы: нет совместимого наблюдателя в заявленном каталоге; чётность числа `a` не восстановлена даже в `auto`. Подробности и фактические run_id — в `previous/...zip`.

## Phase A — неизменяемость старой базы

Сначала выполнить исторический replay старой версии с теми же digest/artifact; не пересобирать старые JSON/AST и не смешивать новый checker с baseline. На новом модуле старые тесты как минимум не ухудшаются; тривиальный all-negative не считается PASS. Все запросы `queries` без меток; решение замораживается ДО holdout; SHA-256 входа, AST, проверки и происхождения записываются отдельно.

## Phase B — формальное ядро

**P0 nullable/ε**: раздельные `S→ab|aSb` и `E→ε|aEb`; явно тестировать `ε`, `ab`, `aabb`, `abab`. Выбирать активный контроль `ε` при конфликте двух гипотез, а не увеличивать длины случайных строк.

**P1 choice/ALT и раздельные пары ролей**: `D→ε|S D P D|A D B D`; контрпример `SB`, положительные `SP`, `AB`, `SAPB`, `ASBP`, `SPAB`. Типизация пары важна; баланс символов по количеству не достаточен.

**P2 альтернативные терминальные рамки**: чётный палиндром `P→aa|bb|aPa|bPb`; тестировать `aa`, `bb`, `abba`, `baab`, `abab` (отрицательный). Единое фиксированное `OPEN/CLOSE` не подходит.

**P3 конечная память**: регулярный `#a(w) mod 2=0` + `(ab)+`; наблюдатель должен открыть конечный переходный процесс либо честно сообщить об отсутствующей конструкции. Никаких специальных feature-флагов `is_even_a`, `dyck2`, `palindrome` в генераторе.

**P4 witness forest**: неоднозначная грамматика `S→SS|a`, слово `aaa` должно сохранить минимум два разных дерева. Отдельно tamper tests: правило, лист, span, тип нетерминала, исходный SHA, альтернативный branch ID, invalid provenance.

**P5 множественные CFG**: `w#reverse(w)`, включение `ε`, ковариантность при одновременном `terminal/role rename`. Ограничить глубину и сохранять `UNKNOWN_BOUND` при слишком больших случаях.

**P6 негативный canary**: `a^n b^n c^n` не является КС. Нельзя объявлять его невозможным для любых наблюдателей; проверяется отсутствие ложного утверждения «вывели эту грамматику как CFG» из случайного конечного совпадения. Негативный контроль не должен ломать способность распознавать конечное подмножество.

## Phase C — однозначный controlled language → formal

После Phase B взять согласованный микрорегламент русского языка с явно размеченными кванторами, типами и предикатами (сначала около 20–30 коротких предложений). Задача: корректная типизация, восстановление логической связки и воспроизводимая привязка каждого фрагмента к исходному байтовому интервалу. Замороженные тестовые фразы не используются при подборе шаблонов.

## Phase D — неоднозначный controlled NL → несколько интерпретаций

Первые эталоны: «Каждый исследователь проверил одну гипотезу», «Некоторые сотрудники не одобрили все заявки», «Все модели не прошли проверку» — последний пример требует особой внимательности к естественной речи и не допускает заранее объявленного единственного чтения. Для первого предложения в данном пакете строго фиксированы три возможные формулы.

Acceptance: (1) больше одного типизированного кандидата при реальной неоднозначности; (2) различающие конечные модели с correct truth vector; (3) прямой отказ при нарушении типов; (4) разные альтернативы сохраняют свои spans и предпосылки; (5) несуществующие типизированные смыслы не выдаются за «доказанные».

## Phase E — естественный текст без контролируемой грамматики

Только когда Phase B–D выполнены. Модель-предлагатель может быть LLM, но её задача — предлагать структуры и указывать evidence; независимый checker не должен доверять её собственным суждениям об истинности. Разрешить `UNKNOWN/NEED_ADJUDICATION` и проверяемые различающие вопросы. Не строить всю универсальную семантику русского языка за один patch.

## Метрики и критерии

Для каждого языка: `TP,TN,FP,FN,UNKNOWN`, числа positive/negative по длинам и классам контрпримеров; отдельно `grammar_structure_found`, `parse_witness_verified`, `ambiguous_forest_preserved`, `renaming_covariant`, `origin_audit`, `replay_match`. Для FOL: `typed_candidate_rate`, `countermodel_recall`, `spans_verified`, `cross-model_status`, `human_interpretation_agreement` (если была человеческая разметка; иначе NULL).

Ложный успех: «очень высокая accuracy» с 1 positive, all-negative, «нет контрпримера» на конечной длине ⇒ глобальное доказательство, `ε`-сбой замазан, или заранее вставленный oracle программы выдан за обнаруженную структуру.

### Остановка

Режим исследовательский и экономный: сначала контрпример/различающий тест, затем bounded поиск; CPU/память ограничить и записать. При новом классе провала сформировать минимальный RCA и одну конкретную правку, а не умножать бессмысленные прогоны.
