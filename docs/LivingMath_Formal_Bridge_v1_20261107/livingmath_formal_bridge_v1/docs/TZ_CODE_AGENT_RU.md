# Техническое задание LM-FORMAL-001

## 0. Заказ и приёмочные цели

**Не писать новый MCP с нуля.** Работать поверх существующего SUTI-Bridge-LivingMath `v0.4.8-developer-preview`, deployment `dyck006-20261106T214503Z`, установленного модуля `observer_synthesis_v1/5-role-branching` и `symbolic_v1`. Сначала проверить реальные версии/API в репозитории; схема из этого документа — **проект**, её нельзя выдавать за уже существующую.

Цель P0–P2: расширить выразимость индуцируемых, **исполняемых и проверяемых** грамматик/автоматов; сохранить multiple parses и typed interpretations без преждевременного quotient; научиться выбирать различающие запросы. После P0–P2 добавить отдельный opt-in мост от естественного текста к *нескольким* FOL-претендентам с независимой типизацией и конечными контрмоделями. Главный результат — контракт и доказательства выполнения, не громкая accuracy.

### Текущие факты (верифицированы на live MCP до данного пакета)

- Dyck(1): конечный контроль 764/764, не универсальная теорема.
- `a^n b^n`, n≥1: 256/256 на непустых строках, а отдельная `ε` дала FP, потому что реальная AST реализовала n≥0.
- Dyck(2): `NO_VERIFIABLE_NEW_OBSERVER` (тогда 0 положительных из 40);
- чётные палиндромы: 0 совместимых из 40 вариантов однопарного каталога;
- even-a parity: нет наблюдателя в `role_branching_ast` и `auto`.
- `white_star_symbolic_observer_synthesize` с `mode=role_branching_ast`, `enabled_builtins=[]` и `holdout_labels_visible=false` — реальный серверный интерфейс; `source/text/SHA` обязательны при регистрации данных.

Считать это исходными воспроизводимыми кейсами; их имена **не должны быть макросами/признаками** в новом индуктивном алгоритме.

## 1. Функциональные модули и границы

### LM-F1. Обобщённая грамматика

Ввести внутренний **typed grammar IR** с конечными алфавитом терминалов `T`, множеством нетерминалов `N`, независимым стартовым символом `S0`, набором продукций с правой частью `Seq(Term | Ref)` и явным `EPS`. Оператор `ALT` — конечное множество продукций, в том числе с рекурсивными подвыражениями; `CONCAT` — сохраняющая порядок композиция.

Разрешать несколько типизированных пар терминальных ролей и симметричные/неодноимённые краевые терминалы. **Не вводить** специальные конструкты `Dyck2`, `Palindrome`, `anbn`. Нетерминалы не должны быть насильно nullable только потому, что рекурсивное поддерево допускает `EPS`.

Усложнение до двух нетерминалов разрешать только при явно контролируемой метрике сложности AST и budget; минимальная модель с одним NT уже покрывает ряд задач. Нужна консервативная политика на леворекурсивные/ε-циклы: не бесконечный DFS, а chart parser (Earley, GLR или эквивалент) с forest и статусом `UNKNOWN_BOUND` при незакончившемся ограниченном поиске.

### LM-F2. Грамматическая индукция, а не импорт оракула

Синтезировать кандидатские AST **из примитивов** `EPS,TERM,NT_REF,SEQ,ALT`, без меток класса языка. Поисковая политика: детерминированная каноническая нумерация по размеру AST, числу терминальных типов, числу NT и рекурсивной глубине; структурные ограничения применяются до дорогого парсинга; отрицательные train-примеры используются для отсечения. Для осмысленного бюджета допустить counterexample-guided refinement, но не использовать тайные builtins (`is_palindrome`, `parity`, `well_nested`).

Зафиксировать полностью объявленный каталог гипотез для каждого шага, реально рассмотренные варианты, отвергнутые witness-контрпримерами, оставшиеся необследованные варианты, состояние бюджета. **Нельзя** интерпретировать `NO_COMPATIBLE_IN_CATALOG` как невозможность CFG. Выбор первого кандидата не уничтожает другие train-compatible AST.

### LM-F3. Конечный автомат как отдельный слой

`DFA(states, alphabet, start, accepting, delta)` с конечным `delta` и trace `q0,a1,q1,...`. Поиск малых DFA по явному числу состояний до fixed max, канонизация изоморфных переименований состояний, независимая проверка транзиций. Для parity должна выводиться двухсостоянийная машина или фиксироваться бюджетное `UNKNOWN`; запрещено превращать это в специальный счётчик для теста.

### LM-F4. Proof objects и независимый checker

Для каждой принятой строки — дерево/packed forest с именами правил, начальными/конечными индексами токенов, terminal-span, `source_sha256`, `start_symbol` и `grammar_sha256`. Для автоматов — трасса состояний. Верификатор находится в отдельном модуле, не импортирует функции поиска; сверяет каждое правило и границы с *замороженным* исходным текстом. При invalid AST/role binding/branch ID/source span/reordered tokens/forged SHA — `REJECTED_PROOF`.

Разделять `ACCEPT_WITH_WITNESS`, `REJECT_COMPLETE`, `UNKNOWN_BOUND`, `UNKNOWN_CYCLE`. Для epsilon-producing grammar возможна неоднозначность с бесконечным числом выводов; её нужно либо компактно кодировать с пометкой о цикле, либо вернуть `UNKNOWN` для перечисления полного леса, не обещая completeness.

### LM-F5. Active discriminators

Для набора несхлопнутых кандидатов `H` выбирать по объявленному конечному бюджету строку `w`, где membership гипотез различается; выделять `ε` как нулевую длину, не как невалидный вход. Возвращать *кандидатский* запрос и вектор предсказаний, **не его правильную метку**. Внешняя разметка (оракул, эксперт, реальные данные) поступает в отдельный train-обновляющий акт и реиндексирует новое поколение гипотез.

Неудачный конечный поиск различителя: `NO_DIFFERENCE_WITHIN_BOUND`, никогда `EQUIVALENT`. Для FOL аналогичный поиск конечной модели `M`, в которой две формулы имеют разные истинностные значения. Кванторы и предикаты должны быть типизированы; область модели и закрытый/открытый мир объявлены явно.

### LM-F6. Formal Interpretation Bridge (НОВЫЙ opt-in)

Контракт входа:

```
TextSource { text_utf8, sha256, spans[], context_refs[], rights }
CandidateProvider { kind: "white_star|external_llm|human|imported", provenance }
```

Выход:

```
FormalCandidate {
 candidate_id, source_ref, signature, formula_ast, assumptions[],
 token_role_links[], construction_trace[], candidate_provider,
 type_status, proof_status, alternative_parse_refs[],
 derivation_hash, limitation_tags[]
}
```

На первом шаге candidate provider может быть внешним компонентом, но он **не определяет математическую корректность**. Известные существующие `symbolic_v1` операторы могут выдавать структурные предложения, но у них сейчас **нет общего доказанного NL→FOL декодера**. Это отдельная архитектурная задача. Typed checker обязан отвергать несортированные аргументы (например `Checked(hypothesis,researcher)`), несвязанные переменные и недопустимые predicate symbols. Исполнение формулы `M⊨φ` оформлять отдельным exact finite-model oracle; у других классов моделей честный unknown.

### LM-F7. Архив и replay

Сохранять append-only: source text/ref/SHA, normalization, typed AST/grammar SHA, seed, search bounds, operator trace, source spans, все альтернативы, countermodels, full and partial witnesses, статус проверок, время/память, independence of verifier, версии ядра. Установленные old run hashes не менять; новую схему версионировать (`formal-grammar-ir/1`, `formal-candidate/1`, `formal-contrast/1`). Replays в отдельном приватном проекте, без перезаписи legacy событий и без запуска кода из загруженного ZIP.

## 2. Предлагаемые, НЕ существующие пока MCP-действия

Следующие имена — API-контракт для проектирования; **не вызывай их как уже установленные**:

```
formal_synthesize(train_ref, constraints, budget) -> synthesis_run_ref
formal_inspect(run_ref, view, page) -> immutable artifact/page
formal_verify(run_ref, proof_ref, source_ref) -> CHECKED_INSTANCE|REJECTED|UNKNOWN
formal_contrast(run_ref, candidate_refs, max_length|max_models, budget)
  -> DISTINGUISHING_QUERY|FINITE_COUNTERMODEL|UNKNOWN_BOUND
formal_interpret(source_ref, candidate_provider, target_signature, budget)
  -> candidate_ref[] (PROPOSED; not semantically proven)
formal_model_check(candidate_ref, model_ref) -> TRUE|FALSE|UNKNOWN|ILL_TYPED
```

Их можно реализовать как совместимый namespace/подсистему, не меняя ABI существующих методов. Доступ к внешним LLM — opt-in и с учётом реального подключения; отсутствие провайдера не блокирует грамматику/верификацию/модельный слой.

## 3. Этапы и проверяемые критерии приёмки

**P0 — ε, типизация, нарушения и replay (обязателен).** Синтезировать/сохранить два несовпадающих начала для `n>=0` и `n>=1`. Проверить `ε` как активный discriminator, что предъявляет реальный предыдущий FP. Внутреннее EPS не делает автоматически старт nullable. Независимый checker отклоняет 5+ видов подделки; старый Dyck(1) не ломается. Исходный замороженный код Белой звезды не менять.

**P1 — мультиветвистость.** Никакого `Dyck2`-знающего builtin. Индуцируемый AST обязан использовать как минимум две различимые роли пар и показывать правильные смешанные вложения. Палиндром — две альтернативные симметричные терминальные ветви; ambiguous grammar `S→SS|a` сохраняет 2 дерева для `aaa`. Separate `grammar recovered` vs `membership correct`. Выполнить query-only positive-enriched holdout с не менее 16 позитивами (где возможно) и эквивалентными по балансировке adversarial negatives.

**P2 — автомат и контраст.** 2-state DFA для `#a mod 2=0`; одна неакцептируемая перестановка/модель не маскируется all-negative. Варьировать роли и alphabet; кандидат, который даёт разные значения в двух доменах, должен выдавать различающий запрос с provenance.

**P3 — controlled NL bridge.** Три варианта «Каждый исследователь проверил одну гипотезу» под одной исходной фразой, не менее двух несходных моделей с truth vectors, явная сортировка, доказанный отказ при поддельном типе; наличие нескольких трактовок в response. В первой версии разрешена внешняя/ручная генерация кандидатов как `PROPOSED`, но тест их **проверки/сравнения** должен быть автоматическим; заявлять «самостоятельное извлечение» можно только при реальном candidate synthesis без шаблонов задания.

**P4 — независимость и безопасность.** Blind holdout, no label leakage, no `is_palindrome` etc., replay_hash PASS; rejected tampering != permission grant; corpus/source rights. Не считать 0 ошибок научным доказательством правильной онтологии.

## 5. Запреты

- Не заменять engine самостоятельной готовой библиотекой `parity/dyck2/palindrome` как распознавателем, а потом заявлять самостоятельное открытие.
- Не стирать различия в грамматических деревьях, версиях интерпретаций, source spans и assumptions.
- Не менять числовую Белую звезду, SUTI, downstream business logic, ledger старых результатов.
- Не прятать CPU-ограничение бесконечным перебором.
- Не объявлять успешный локальный proof checker доказательством уникальности грамматики, намерения автора или универсальной семантики.
