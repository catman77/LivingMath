# LivingMath / Белая звезда — Formal Bridge v1

**Дата:** 2026-11-07.  **Статус:** проект архитектуры и воспроизводимый reference-acceptance; не patch установленного MCP.

## Что внутри

- `docs/THEORY_RU.md` — математический объект интерпретации; отношения между трактовками; строгость и граница доказуемости.
- `docs/TZ_CODE_AGENT_RU.md` — техническое задание на реализацию в LivingMath MCP и этапы приёмки.
- `docs/PROMPT_CODE_AGENT_RU.md` — промпт для кодового агента, работающего с реальным репозиторием.
- `docs/EXPERIMENT_PROTOCOL_RU.md` — протокол испытаний и защиты от ложных успехов.
- `docs/RESULTS_RU.md` — выполненные тесты, выявленные ограничения и незапущенные проверки.
- `src/reference_kernel.py` — самостоятельный эталонный интерпретатор CFG/DFA и типизированных FOL-формул.
- `src/run_acceptance.py` — автономный прогон тестов + `results/reference_acceptance.json`.
- `fixtures/quantifier_ambiguity.json` — один текст, три формальные трактовки, модели и точная привязка к исходным байтам.
- `fixtures/active_queries.json` — дифференциальные запросы для грамматик; `fixtures/synthesis_contract.json` — классы конструкторов и бюджет поиска.
- `previous/formal_language_acceptance_20261107.zip` — неизменённый предыдущий пакет приёмки с dataset-генераторами и протоколами действующего MCP.

## Воспроизводимость

```bash
cd livingmath_formal_bridge_v1
python3 src/run_acceptance.py
```

Без зависимостей за пределами Python stdlib. В `results/reference_acceptance.json` сохранены 225 независимых assert-проверок (в том числе многие per-witness), 9450 конечных проверок membership, пары моделей/контрмоделей и различающие строки. Статус проверок — **REFERENCE_PASS**, не `MCP_ACCEPTED`.

## На что НЕ претендует пакет

1. Не существует общедоказанной идентифицируемости произвольной КС-грамматики по конечному набору строк.
2. Эталонные грамматики заданы явно — код в `src/reference_kernel.py` **не обучается**, поэтому его успех нельзя выдавать за успех открытия грамматики.
3. В `fixtures/quantifier_ambiguity.json` три чтения русского текста определены вручную. Это тест на будущий `text→formal-candidates` MCP, **не результат существующего** `symbolic_v1`.
4. Генерация Белой звездой нескольких кандидатов не даёт им автоматически статуса логического следствия из текста. Проверить истинность FOL-формулы *в заданной конечной модели* можно, проверить *правильность человеческой интерпретации* без внешнего критерия нельзя.
5. Новый кодовый агент должен сохранять старые корпуса, исходный числовой Белой звезды, private source constraints, frozen replay и все результаты старой приёмки.
