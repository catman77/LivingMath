# Threat model and supported boundary

Single OS owner, local POSIX filesystem and a trusted installed package. Untrusted input consists of candidate JSON, source text, task scopes and imported bundles. No arbitrary source Python is executed. The bounded program is the original SHA-pinned rotate_left only. Schema sources are limited to the two existing reviewed SUTI schemas; external/local recursive schema references are unsupported. No new predicate or DSL is introduced.

Input JSON rejects duplicates, nonfinite numbers, depth >48 and payloads >2 MiB. Source content is limited to1 MiB. Project IDs are slugs; object paths are SHA addresses. Symlink files, unsafe ZIP paths/duplicates, oversized expansion, changed core/source/scope/evidence and unknown schema versions are rejected or held. A check requires an explicit exact-task review. No result grants permission to execute external actions.

The journal is hash-chained and committed with file+directory fsync and atomic rename under flock. A crash before commit may leave an unreferenced object; exports include only committed refs. A retry after commit returns the original result. Hashes detect tampering relative to a trusted head; they are not digital signatures against a malicious OS owner who rewrites every hash.

Offline replay uses installed pinned code, compares bundle core bytes without importing them, and blocks socket/process/dynamic-library operations in the replay thread. It neither logs in nor loads a model. Source publication requires both source rights and audience policy. Missing bytes are explicit dependencies, never reconstructed. Conservative tests cover common credential/email/phone/home-path patterns; these guards are not a general PII detector. Owners must inspect exported content before sharing. Imported source bytes are not automatically safe/public because they passed a mathematical check.

MCP adds owner-authenticated tools only. The existing Landlock read boundary is extended to the exact immutable assurance release layer; no executor/oracle/private credentials are added. Single-owner OAuth authorizes access to all of that owner's assurance projects; project separation prevents cross-project evidence references, not different-user authorization. Public quick-tunnel URLs are ephemeral and require reconnecting ChatGPT when changed. TLS/OAuth acceptance is recorded separately from local unit tests.
