# RCA UDAV Core PATCH001

## Причины исходных дефектов

Старое symbolic расписание выбирало operator без полного учёта его конечных
параметров и всех сохранённых выходов. Повторные/пустые состояния вытесняли
полезный фронтир. Исправлен только opt-in scheduler: независимые cursors на
actual node/op, дедупликация точного аргумента, регистрация всех output parts,
seeded order для множества operators. Новых фундаментальных операций нет.
Raw hash отличает байты, но не scientific structure. Теперь quotient объявлен
отдельно, source/history не склеиваются, отсутствие structural observer явно
undefined. В numeric прежняя память не учитывала exact CAT source-ID пару.
Новая динамическая policy вставляет этот критерий строго после первичного
novelty; неоднозначные aliases сохраняются как множество альтернатив.

## Отрицательные промежуточные результаты сохранены

1. Первое расписание longest-first не расширяло обе внутренние SPLIT ветви на
seed120. Сохранены frontier-longest-v1.py, неуспешная MCP трасса и лог. Заменено
на справедливые family rounds/FIFO открытия; все шесть real MCP проверок прошли.
2. Ошибочный envelope отрицательного ответа не содержал обязательный run_id.
Исправлен адаптер, повторный реальные foreign/hash/key проверки PASS.
3. Первый precommit alias fixture содержал повторённые coordinates, запрещённые
старым контрактом. Отказ произошёл до поиска; старые SHA/fixture/trace сохранены.
Новые различные quarter-turn vectors зафиксированы до исполнения, original
контракт не ослаблялся. Оба precommit документа в fixtures/.
4. Дополнительный harness ошибочно считал max_steps=0 недопустимым. Старый
контракт разрешает такой ограниченный zero-work запуск; он сохранён отдельной
QA записью. Исправлен тест на действительно недопустимый -1. Лог первого теста
и ответы не удалены, новые негативные запросы не добавляют историю.
5. Первая дополнительная legacy-команда не получила LM_ENGINE017_POLICY и
упала в25 fixture setup без /tmp/lm017_path. Указан существующий оригинальный
pre-registration.json, не синтетическая замена. Повтор затронутых55 тестов PASS;
окончательный полный лог приведён в TEST_RESULTS.json и delivery.
6. Одна техническая попытка сборки из private cwd не нашла pyproject.toml.
Сборка повторена из checkout; все новые module bytes совпадают в source,
wheel и установленном runtime. Установленный final wheel:485 PASS.

Эти отказы не переименовываются в PASS. Финальная матрица относится к
исправленной реализации и явно зафиксированным повторным запускам. Ограничения
CPU-bound replay и semantic/R3 вынесены в отчёт. Новых model calls нет.
