# ТЗ PATCH-001: ограниченная композиционная индукция грамматики и диагностика поиска

## Цель

Доработать **существующий** `symbolic_v1`, чтобы он мог обнаруживать содержательные отношения, выходящие за пределы одиночного предиката `endpoint_equal`, и честно предъявлял области неопределённости. Исправить бессодержательный расход шагов при отсутствии новых кандидатов. Сохранить интерфейсы и математическую строгость.

## Неизменяемые компоненты

- Numerical White Star `base_v1`, `cj_v1` и его native hash/binding.
- Существующие методы `white_star_symbolic_explore/inspect/replay` и их request/response schemas: менять лишь аддитивно, по возможности.
- Точная S/P семантика, буквальная/α/normal form эквивалентности, DAG provenance, hash chain, export/replay.
- Строгое отделение `proved_exact`, `observed`, `empirical`, `underdetermined`; ни один эмпирический прогноз не объявлять теоремой.
- Отсутствие LLM внутри изолированного worker, отсутствие сетевых вызовов, существующие лимиты CPU, RAM, steps, nodes.

## Изменение A: композиционная грамматическая гипотеза

1. Разрешить правилам гипотез ссылаться на *отношения между позициями и фрагментами*, а не только на один локальный признак. Примитивы берутся из уже имеющихся наблюдателей (`alpha_pattern`, `composition`, `substring_contexts`, `hierarchy`) и обратимого `REVERSE`, а не из заранее написанной библиотеки готовых грамматик.
2. Обеспечить ограниченный синтез композиций уже наблюдаемых отношений с максимальной глубиной `max_rules` и явным бюджетом. Не запускать полное перечисление всех CFG/regex/AST; строить кандидатов из конкретных различающих свидетельств положительных и отрицательных примеров.
3. В качестве отдельного теста должна быть *возможна* гипотеза рекурсивного согласования концов: пустое слово или один символ; если края совпадают, проверить внутреннюю часть. Не хардкодить «палиндром» как готовую метку/правило: вывести правило из данных, сохранить трассу источников и проверяемый операторный вывод.
4. Сохранять **множество** несовпадающих train-compatible гипотез, если данные их не различают, с явным контрпримером/новым зондом для разведения. Не выводить `UNIQUE` из идеального train accuracy.
5. В `grammar` вернуть необязательные поля `relational_rule_ast`, `rule_witnesses`, `scope`, `counterexample_candidates`, `hypothesis_complexity` и причину ограниченности (не ломая старые consumers).
6. Статус `EMPIRICAL` у одного выбранного правила не должен скрывать `UNDERDETERMINED` всего семейства. Рекомендуется явное `candidate_status` vs `identifiability_status`.

## Изменение B: независимая оценка после заморозки

1. Проверить, что прогнозируемые слова недоступны при выборе/обучении гипотезы; заморозить `hypothesis_digest` до вычисления predictions. Выявленное свойство изоляции сохранять тестом.
2. Предусмотреть стабильный read-only экспорт замороженной гипотезы и её предсказаний; оценку `accuracy`, `balanced_accuracy`, `false_positive_rate`, OOD-length, renaming consistency должен выполнять внешний держатель скрытых меток. Сервер не должен утверждать результат heldout без меток.
3. Тест на длины 4 (train) и 6/8/10 (holdout), с контрпримерами, совпадающими по первым и последним символам, но различающимися в середине.
4. Отдельный контроль: перестановка названий токенов A↔X, B↔Y сохраняет структурные вердикты и выбранные классы гипотез; renaming scope=global и local тестируются отдельно.
5. Минимальный acceptance: на фиксированном heldout из `04_TEST_PROTOCOL_RU.md` верный классификатор должен классифицировать все примеры; если наблюдений недостаточно для выбора уникального правила, система обязана показать конкурирующие гипотезы и запросить различающий зонд, а не молча выдавать уверенное ложное обобщение. При недоопределённости допустим статус inconclusive вместо искусственного PASS.

## Изменение C: структурные сравнения историй

1. Добавить безопасную функцию/представление для сравнения двух сохранённых run IDs (либо повторяемый inspect-based report, если отдельная команда избыточна): `same_literal`, `same_alpha`, `same_sp_normal_form`, `same_history`, `same_op_trace`, `same_observer_signature` + контрпримеры с исходными byte spans.
2. Для сравнения `ab/ba` и `cd/dc` выводить не разность агрегатных метрик, а explicit witnesses для порядка, композиции, нормальной формы и маршрутов редукции.
3. При инверсии S↔P для всех S/P-слов учитывать, что `q` меняет знак; сохраняется равенство нулю, а не всегда числовой `q`.
4. `history_identity=provenance` должен сохранять разные пути к одному слову, `history_identity=word` — допускать буквальное объединение. Проверить оба без дополнительной насильственной канонизации.

## Изменение D: диагностическое завершение при насыщении

1. При локально исчерпанных реально доступных кандидатах возвращать новый `halt_reason=SEARCH_SATURATED` (или `NO_NOVEL_CANDIDATES`) и finite certificate: текущий word/node, набор допустимых операторов, проверенные варианты, причины отклонений.
2. Дедупликация не должна уничтожать новые provenance-paths, когда включён соответствующий режим.
3. Нельзя объявлять глобальную невозможность продолжения по локальному ограниченному набору кандидатных операций; статус явно local/bounded.
4. Не менять алгоритм выбора Удава ради удобства тестов: диагностический слой должен отражать фактические candidate sets/decisions.

## Изменение E: литературный корпус

1. Передавать текст напрямую, не через 2D-семантические координаты.
2. Сохранять UTF-8 byte offsets, нормализацию NFC/none, строки, разделы/секции и (при наличии) типографический layout.
3. Для Малларме проверить контроль с переставленными строками и с буквами, заменёнными при сохранении частот/границ; обозначить, какая именно структура различается.
4. Нострадамус — последующая исследовательская приёмка, не блокер PATCH-001: текст и издания должны быть независимы от предсказаний об исторических событиях.

## Приёмочные ограничения

- Никаких новых движков/модулей разработки «с нуля», no full enumeration, no LLM re-ranking.
- Быстрые unit/property tests (< 2 мин на типичном dev workstation), отдельный bounded live smoke.
- Изменения в source manifest, version, hashes, changelog, тестовом отчёте.
- Откат на предыдущий профиль должен давать тот же replay_digest; старые run IDs и White Star истории остаются читаемы.
- Все утверждения об успехе сопровождаются фактическим файлом результата и воспроизводимым командным вызовом.
