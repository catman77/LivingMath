# Промпт кодовому агенту — LivingMath SYMBOLIC_V1 PATCH-001

Ты работаешь в текущем репозитории действующего MCP LivingMath v0.4.0. Получен ZIP `LIVINGMATH_SYMBOLIC_V1_ACCEPTANCE_PATCH001_20261105.zip`. Прочитай `README_RU.md`, `01_ACCEPTANCE_REPORT_RU.md`, `02_TZ_PATCH001_RU.md`, `04_TEST_PROTOCOL_RU.md`.

Цель — **точечная доработка работающего symbolic_v1**, а не новая архитектура. Сначала установи реальные пути модулей и tests в репозитории, составь map файлов. Сверь работающие схемы, fixture hashes, численный kernel binding и legacy profile hashes. Не копируй заново ядро и не замещай существующие механизмы собственным DSL/перебором.

Критический найденный кейс: на training `{ABBA,BAAB,AAAA,BBBB}` positives и `{AABB,BBAA,ABAB,BABA}` negatives модель выучила только `endpoint_equal`, дала ложноположительные `ABCBCA`, `ABABBA`, `BAABAB` на отложенных данных. Это не баг математики, а ограничение поиска грамматики. Расширь индукцию от локальных признаков к ограниченной композиции наблюдаемых отношений (включая внутренние фрагменты/зеркальные контексты) с точными свидетелями. Не называй конечные samples доказательством уникальности грамматики. Предпочитай честный набор конкурирующих гипотез + активный различающий запрос, если данных недостаточно. Не хардкодь палиндром как готовый тип.

Второй кейс: пара композиционных S/P-слов при `history_identity=word` исчерпывает 128 шагов, оставаясь в девяти состояниях. Выведи диагностику насыщения **локального** пространства кандидатов без претензии на глобальный no-go. Сохранить `provenance` как отдельную семантику и независимые paths.

ОБЯЗАТЕЛЬНО: прежде чем менять код, запусти текущие регрессионные тесты и сохрани baseline. После — выполнить тесты по `04_TEST_PROTOCOL_RU.md`, затем проверить старые команды `white_star_explore/inspect/replay`, текущие `white_star_symbolic_explore/inspect/replay`, границы CPU/памяти, source SHA mismatch, Unicode, deterministic digest, no LLM/network, и сохранность исторических run IDs.

Не требуется долгий overnight regression, многомиллионные траектории или расширение аппаратной инфраструктуры. Приоритет: один работающий, конечный, воспроизводимый механизм вместо десяти страниц красивых обещаний.
