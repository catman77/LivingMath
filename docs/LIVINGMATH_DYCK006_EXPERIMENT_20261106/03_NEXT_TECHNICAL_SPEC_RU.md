# ТЗ будущего экспериментального изменения: ROLE-SENSITIVE BRANCHING GRAMMAR

СТАТУС: ПРОЕКТ ТЗ на основе EXP-DYCK-006. На актуальном `v0.4.7` НЕ реализовано. Не устанавливать/не объявлять принятое без отдельного теста.

## 1. Цель

Научить `observer_synthesis_v1` синтезировать **из данных** типизированные ориентированные правила построения структур, использующие переменные границы разрезов и несколько независимых рекурсивных вызовов. Базовый контроль: Dyck на S/P без готовых роле-чувствительных функций в `enabled_builtins` и без явной зашитой в продакшн процедуры `is_dyck`.

## 2. Новые примитивы для кандидатного AST

Генератор должен различать следующие типы:

* `ATOM_ROLE(atom, role)` — проверяемое соответствие атома **заявленной роли**, а не тест равенства атомов друг другу; кандидатские роли OPEN/CLOSE порождаются из ограниченного каталога, роль никогда не берётся из heldout-метки.
* `SPLIT_AT(input, k)` — разрез с переменным типизированным индексом k. Все части с точными source spans/UTF8 offsets. Выбор k выполняется в конечной области с флагами исчерпания бюджета.
* `CONCAT` — буквальное восстановление исходного слова. Не допускается считать реконструкцию доказанной только по хешу.
* `BRANCH_AND(R(left), R(right))` — допускает ДВА независимых рекурсивных дочерних фрагмента с неизменяемой меткой происхождения.
* `FINITE_EXISTS(k)` — проверяемое существование разреза, отличное от бездоказательного поиска и от механизма вероятностной классификации.
* `EPS_BASE` — точное основание пустого слова; `ROLE_BASE` и `RECURSE` с доказанным сокращением длины.

Новые примитивы НЕ означают заранее заданный предикат Дика. Должны порождаться несколько альтернативных типизированных схем, включая заведомо несовместимые; каждая отбрасывается с counterexample ref. Не вводить LLM в исполняющий verifier, не использовать `eval`/плагины из архива, не скрывать дополнительный builtin с готовым результатом.

## 3. Семантика и сертификаты

Разделить три статуса:

* `CANDIDATE_GENERATED`: AST синтаксически корректен, но ничего не доказано;
* `TRAIN_COMPATIBLE`: на конечном обучении без противоречий, статус эмпирический;
* `CHECKED_FINITE_INSTANCE`: независимый verifier подтвердил конкретные трассы и конечное утверждение, **не** универсальный закон/уникальная грамматика.

Сертификат положительного случая должен включать: дерево SPLIT со СПИСОЧНЫМИ дочерними ветвями; роли OPEN/CLOSE; все токенные и байтовые диапазоны; исходный хеш; точные результаты каждого CONCAT; меру убывания на каждой рекурсивной дуге.

Сертификат отрицательного случая должен доказывать отсутствие пригодного разреза **в рамках выбранного конечного AST и заявленных бюджетов**. В режиме полного покрытия короткого слова — таблица всех подинтервалов, в ином режиме — честный `UNKNOWN`, не произвольный `False`. `reference/dyck_certificates.py` — только независимый oracle: продакшн-генератор обязан сформировать свои свидетельства и независимый checker перепроверить семантику без делегирования вывода обратно генератору.

## 4. Типизированное переименование и инвариантность

Потребовать:

* при глобальном S↔P **с фиксированными** ролями OPEN=S/CLOSE=P меняется принадлежность языка; `SP=True`, `PS=False`;
* при одновременном переименовании атомов И ролей предсказание инвариантно;
* равенство нормальных форм (`NF(SP)=NF(PS)=EPS`) не является основанием для равенства грамматических оценок.

Прозрачно отделить `LITERAL_ROLE_SENSITIVE`, `ALPHA_RENAMING_EQUIVARIANT` и `NF_INVARIANT`: это разные контракты.

## 5. Приёмочные тесты (P0)

1. **Самый короткий контрпример**: train `SP=True, PS=False`, generated catalogue должен содержать хотя бы одну **ориентированную** гипотезу, различающую их, и отчёт обо всех несовместимых гипотезах. Нельзя считать это уникальной грамматикой.
2. **Ветвящееся свидетельство**: `SSPPSP=S(SP)P(SP)` принимается только с двумя проверенными рекурсивными ветвями, не путать с простой цепочкой вложения.
3. **Обучение на 84 словах** всех длин 2,4,6 и отдельный sealed-holdout из 256 слов длины 8: TP=14, TN=242, FP=FN=0. `accuracy` и `balanced_accuracy` выводить вместе. Не передавать heldout labels в queries.
4. **Негативы**: намеренно неверная роль, неправильный SPLIT, пропущенная вторая ветвь, неверные UTF-8 spans, неправильный SHA, одна редукция NF вместо ориентированного доказательства, повреждённое отрицательное DP-свидетельство, превышение глубины/бюджета; всё должно `REJECTED` или `UNKNOWN`, не `CHECKED_INSTANCE`.
5. **Независимая проверка**: `observer_verify` не доверяет digest; новый verifier не использует решатель, который выдал свидетельство. После пересчёта внешнего SHA поддельная трасса всё равно отвергается.
6. **Контроль утечки**: `holdout_labels_read=false`, `hypothesis_frozen_before_queries=true`, `execution_permission=false`; конфликтующие train метки и отсутствие данных не замазывать классификацией.
7. **Отчёт о поиске**: `max_*`, `untried` AST, `search_status`, `counterexample_train_refs`, `candidate_budget_exhausted`. Никаких заявлений `GLOBAL_EXHAUSTION` при bounded catalog.
8. **Регрессия**: прежние PAL/COPY и SP-комплексы работают; исходные `symbolic_v1` и численные профили не переписываются; сохранён project isolation, replay, idempotent request_key.

## 6. Исследовательская приёмка (P1)

На горизонтах N=1..6 восстановить конечные классы допустимых продолжений: N+2 классов по `R_u={v|uv∈D}` для префиксов и суффиксов длины≤N, включая один погибший класс. Это должен быть **тест на реально построенные отношения продолжений**, а не просто встроенная проверка длины или готовая арифметика высоты.

## 7. Сопровождение и форма сдачи

Отдать исходный патч, `README`, TS/JSON schemas, код independent checker, реестр run IDs и SHA256, `tests` с живыми запросами нового `request_key`, а также отчёт с FP/FN/TP/TN, документацией ограничений и явной фразой `UNIVERSAL_INVARIANT=false` для конечных проверок.

Окончательный критерий: **автоматическое порождение** направленной двухветвевой композиции, а не внедрение специального Dyck-решателя как очередного скрытого builtin.
