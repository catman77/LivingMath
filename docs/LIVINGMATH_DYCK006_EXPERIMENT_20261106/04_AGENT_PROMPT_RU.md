# Промпт кодовому агенту — экспериментальное расширение после DYCK-006

Ты работаешь с действующим репозиторием LivingMath MCP. Не считай внедрённым то, что приложено в ZIP: здесь только независимые reference/oracle и воспроизводимый RCA для релиза v0.4.7.

1. Открой `01_REPORT_RU.md`, `02_FORMAL_NO_GO_RU.md`, `03_NEXT_TECHNICAL_SPEC_RU.md` и `reference/dyck_certificates.py`. Проверь, что текущий `observer_synthesis_v1` реально порождает только equality/fragment/inner-recursion-кандидаты в 84-word Dyck training и что SP/PS логически недифференцируемы внутри этого каталога.
2. Добавь минимальный слой типизированных ролевых атомов, проверки границы разреза, **двух независимых рекурсивных ветвей** и конструктивного сертификата. Не подменяй задачу вшитой функцией `is_dyck`, `pair_0_max`, однострочным арифметическим фильтром или полным перебором всей грамматики мира.
3. Сохрани прежний verifier и отдельный независимый checker нового сертификата. Он проверяет полные токенные/byte spans, отсутствие циклов без убывания длины, оба дочерних поддерева и отрицательные таблицы DP. Не доверяй внешнему SHA.
4. Используй train ref `596fa9621ae7cd197ce0c999a6d03ac406b313ffa351a1107f9807d709f3434e`, holdout ref `e956883b11ac2b73162fb9f55874f2918f7d6aa8d5755dadbe5bcf58e3bb1073`. Для каждой повторной приёмки нужен НОВЫЙ `request_key`; исторические run IDs не замещай.
5. Начни с двуметочного контрпримера SP=True/PS=False. Затем `SSPPSP` с двумя ветвями. Только после этого 84→256 и тест конечных классов продолжений. Сохранить все непрошедшие гипотезы с counterexamples и причины отказов.
6. Не утверждай, что нашёл единственную или универсальную грамматику. Достаточно предъявить одну самостоятельно сгенерированную типизированную схему, которая удовлетворяет train и проверяется на sealed holdout, при этом происхождение AST и отрицательные контроли должны быть строгими.
7. Возвращай единый ZIP с кодом патча, тестами, run IDs и QA-отчётом. Если эксперимент не проходит — приложи честный RCA и минимальную неработающую конфигурацию вместо заявления об успехе.

Важно: внешнее исследование Нострадамуса продолжать только после проверки правил для **ориентированной** грамматики и корректного отображения token hierarchy / α-представления. В текущем API это ещё не реализовано.
