# RCA: чем именно была вызвана новая формализация?

7 ноября 2026 года. Сравниваются `source_only`, `white_star_structural`, `matched_ablation` из независимого пилота `nl_independent_eval_20261107`. Исходный сервер: v0.4.10-developer-preview / `nl002-20261107T060243Z`. Результат исследований не равен доказательству смысла или теореме о всех языках.

## 1. Новое воспроизводимое наблюдение

Короткий независимый эксперимент с замороженными **эталонными AST**:

1. Из ранее составленного до генерации набора `GOLD_AMBIGUOUS_PRECOMMITTED.json` извлечены узкие FOL-формулы U21–U25.
2. Для каждой вычислен SHA256 канонического JSON и сопоставлен с реальным ранее сохранённым `source_only` candidate SHA256 из `AMBIGUITY_SCORES_PARTIAL.json`. Получено 5/5 совпадений.
3. Ровно один примитивный оператор (транспозиция внешних двух кванторов) применён к базовому AST; тело формулы и связи переменных сохранены без изменений.
4. SHA256 каждого результата совпал с ранее сохранённым *White Star trace-derived wide candidate* (5/5) и с заранее указанным вторым gold AST.
5. Различие широкого и узкого чтения проверено на всех моделях с двумя непустыми сортами по 1, 2, 3 элемента: 530 моделей на фразу, 176 различий. Пример на двух исследователях и двух объектах: `P(0,0),P(1,1)` делает `∀x∃y P(x,y)` истинным, `∃y∀x P(x,y)` ложным.

| U21 | да | да | 176/530 |

**Логический вывод (для непустых сортов):** `∃y∀x P(x,y) ⇒ ∀x∃y P(x,y)`; обратное неверно, как показывает диагональная контрмодель. Широкое чтение не просто новая запись той же формулы, а строго более сильное условие.

**Научный вывод:** на этих пяти случаях результат White Star B полностью объясняется оператором `SWAP_QUANTIFIER_SPINE`, доступным любому формальному инструменту. Это не исключает, что White Star полезна для других, более сложных структур или для выбора/приоритизации кандидатов. Иначе говоря, **incremental value зафиксировано как NOT_ESTABLISHED**, а не `universal failure`.

## 2. Найденный дефект существующего экспериментального дизайна

GitHub исходники `catman77/LivingMath` (проверены 7 ноября):

- `src/lm_suti_assurance/nl_proposal/decoder.py`, `build_request` (около строки 81): при `policy.mode=matched_ablation` провайдеру отправляется `list(reversed(trace['source_order']))` вместо исходного порядка. **Тем самым меняется вход LLM**.
- В том же файле `decode` (около строки 63) вызывает `build_move(..., placebo=True)` для ablation.
- `build_move` (строки 18–39) в placebo разворачивает `permutation` при построении нового AST. **Одновременно меняется декодирующий оператор**.

Следовательно, B и C изменяют **как минимум два** причинно значимых фактора: `provider input` и `decoder permutation`. Это не controlled single-variable ablation. Факт совпадения B/C по AST на первых 20 текстах доказывает только равенство полученных строк AST и конечных векторов в тех условиях; не изолирует работу White Star.

Текущая цепочка `TRACE_LINK_CHECKED` подтверждает корректную привязку к вычислению/источнику. Но она не подтверждает ни источниковую допустимость перестановки, ни оригинальность оператора. Точность формализации и trace provenance должны оставаться независимыми полями.

## 3. Почему не удалось просто завершить прежний C

Завершённый C-запуск (U21–U26), `run_ref=076ccc229e6c661dae47459449ffc28f5e499f90c68ffe03bb10cc77a7f2ef46`, ранее имел `COMPLETED`. Повторный вызов `formal_nl_inspect` и даже `bridge_system_status` через текущее MCP подключение возвращают внешнюю инструментальную ошибку `The tool failed internally`. JSON-ошибка самого backend и серверный RCA недоступны. Возможны connector, tunnel, сеть или server; **не установлено**, какая часть отказала. Старый C результат нельзя приписать B, повторять LLM не следует.

## 4. Реальная граница нового теста

В этом пакете зафиксирована **детерминированная локальная реконструкция AST**, хеши которых проверены по сохранённым real MCP результатам. Исходный `raw_output_sha256` provider receipt и реальные `source_order` всей трассы не извлечены. Поэтому называть этот локальный результат полной `same-frozen-receipt` приёмкой нельзя. Следующий эксперимент должен проверять её прямо в сервере.

Открыты также независимая человеческая оценка семантической допустимости и степень обобщения за пределы шаблонных двухкванторных фраз. U26 исключён: его первоначальный gold ошибочен, он не исправлялся постфактум в исходном файле.

## 5. Практическое решение

Не расширять ещё раз выборку похожих `∀∃` примеров. Это будет повторение ожидаемой тривиальной операции. Реализовать `formal_nl_redecode`: нулевую стоимость LLM при единичном frozen receipt и четыре arm (baseline, реальная trace, одна sham perturbation, полное примитивное closure). Добавить классификатор finite relation (`SAME`, `WEAKER`, `STRONGER`, `INCOMPARABLE`, `UNKNOWN`) и отдельный внешний human licensing. Параллельно восстановить C, не повторяя inference.
