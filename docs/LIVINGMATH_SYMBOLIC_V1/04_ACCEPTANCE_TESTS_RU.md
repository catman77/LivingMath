# План проверки: SYMBOLIC_V1

## 0. Тестовый порядок

Первым запускать `python checks/check_fixtures.py`. Он проверяет факты о S/P-словах и α-классах **без MCP**. Затем property/unit, затем интеграционные и replay, затем слепые грамматики. Нельзя использовать ожидаемые итоговые метрики старой Белой звезды как oracle для нового движка.

## 1. Детерминированные S/P и структурные контроли

| ID | Вход | Строго ожидаемое |
|---|---|---|
| T01 | `SSPP`, `SPSP`, `PPSS`, `PSPS` | все q=0, нормальная форма ε; буквальные слова различны |
| T02 | `SSPP` vs `SPSP` | α-классы различны как шаблоны повторений, даже при одинаковом q |
| T03 | `ABBA` vs `BAAB` | изолированные α-классы совпадают: `(0,1,1,0)` |
| T04 | `AB|AB` vs `AB|CD` | локальные построчные α-классы могут совпадать, но глобальные — **не совпадают** |
| T05 | `a=SSPP,b=SPSP` | `q(ab)=q(ba)=0`, `ab != ba`; префиксные истории различаются |
| T06 | любая строка w, k | `CONCAT(SPLIT(w,k))=_lit w` |
| T07 | любое S/P-слово w | `q(REDUCE_SP(w))=q(w)`, `normalize(normalize(w))=normalize(w)` |
| T08 | вставить SP или PS в любую позицию w | нормальная форма та же, исходная история другая |
| T09 | `SP_INV(w)` | `q` меняет знак; `SP_INV(SP_INV(w))=_lit w` |
| T10 | α-биекция алфавита | канонический класс и отношения тождества сохраняются |
| T11 | неполная статистика контекстов | пометка `UNDERDETERMINED` вместо «доказано» |
| T12 | REDUCE неоднозначным порядком пар | нормальная форма одинакова; журналы редукции могут отличаться |

Для property-based тестов: короткие произвольные слова длиной 0–40, seeds минимум 30, случайные split positions, insertion positions, renaming bijections, разные группировки; сохранять падающий минимальный пример. Можно использовать стандартную библиотеку, стороннюю property library только если уже есть в репозитории.

## 2. Интеграционный MCP

**IT01** Регистрируем отдельный test-project штатным инструментом, отправляем `white_star_symbolic_explore`, ждём `COMPLETED`, получаем `run_id` и хотя бы один `structural_observation` с точным token/source witness. Секреты/личные данные не нужны.

**IT02** Повторяем с тем же `project/request_key/payload`: идемпотентность, без дублирования run (или поведение, строго согласованное с действующим assurance contract).

**IT03** `inspect(operations|observations|claims|grammar|evaluation)` умеет pagination, не смешивает provenance и интерпретацию.

**IT04** `replay` с тем же snapshot и seeded алгоритмом воспроизводит структурные подписи и digest; wall time не обязан совпадать.

**IT05** Отрицательные запросы: неверный sha256, пустой alphabet, неизвестный operator, превышенный бюджет, недопустимый span, разомкнутая история, `REDUCE_SP` вне S/P → типизированная ошибка, без повреждения сохранённых записей.

**IT06** Frozen baseline: старые `white_star_explore` и `white_star_inspect` принимают прежние формы запроса; из frozen numerical kernel файлы не менялись. Если текущий manifest изменён по независимым причинам, отдельно зафиксировать baseline from this checkout, diff и причину; не подделывать hash.

**IT07** `max_steps`, `max_word_tokens`, `max_nodes`, CPU/wall/memory: запрос прерывается безопасно, возвращает ограниченный отчёт без hanging/сети.

## 3. Blind grammar tests — нельзя подсказывать ответ

Генератор тестов — независимый компонент test harness; исследуемому ядру предоставляются **только train samples**. Для каждого класса заранее фиксировать семена, train/validation/test, размер выборки и максимальную длину. Модель/правила должны быть заморожены до раскрытия теста. Минимальные семейства:

- **G1: периодический язык** `(AB)*` с разными длинами, скрытым биективным переименованием токенов в test. Нужна проверка способности переносить структуру повторений, а не запоминать конкретные буквы.
- **G2: согласованность дальних концов** `A u A` или `B u B`, где `u` — произвольная цепочка из двух символов. Тренировочный диапазон длин короче тестового; отрицательные примеры с разными концами. Паттерн должен проверяться за пределами локального биграмма.
- **G3: скобочная вложенность (Dyck-1)**: последовательности открывающих и закрывающих скобок с валидными префиксами и нулевым конечным балансом. Отрицательные примеры со сбалансированным общим счётом, но отрицательным префиксом. Важно: грамматика скрыта, нельзя просто вшить parser Dyck как ответ; тест фиксирует переносимость структурных наблюдений.
- **G4: несовместимые гипотезы:** крошечный корпус, допускающий минимум две разные грамматики. Правильный исход — `UNDERDETERMINED`, с конкурентными моделями или явным контрпримером уникальности.

Для честности: отрицательные примеры не должны тривиально отличаться по длине или общей частоте символов. Достаточно лёгкого balancing/ranking генератора, не нужно усложнять систему до «универсального бенчмарка». Минимум 3 независимых seed для smoke, 20+ для исследовательского отчёта, если вписывается в бюджет.

### Метрики

- membership accuracy и balanced accuracy на sealed test; для вероятностных моделей — next-token negative log-likelihood на том же test;
- число заявленных правил с воспроизводимым свидетелем, false-positive rate правил на отрицательных примерах;
- устойчивость к α-переименованию и перестановке train-примеров;
- sample efficiency: число train-слов для фиксированного порога качества;
- стоимость по CPU/wall/max RSS и длине программы;
- compare vs `unigram`, `bigram`, `simple_context`, плюс прежний 2D baseline (только если сопоставим по интерфейсу).

**Условие для заявления о выигрышах:** не меньше одного семейства, где на нескольких независимых seed статистически и практически обнаружено преимущество над лучшим применимым baseline при одинаковом бюджете; показать интервалы/разброс и отрицательные случаи. Если результата нет — честно вернуть `NO_EVIDENCE_OF_GAIN`, но инженерный P0 всё равно оценивается отдельно.

## 4. Реальные тексты — только после G1–G4

- **Малларме:** сохранять исходную орфографию, фрагменты и порядок; если нет доступной page geometry, `layout_status=UNAVAILABLE`. Слепое кодирование без semantic axes, затем reveal-интерпретация.
- **Нострадамус:** фиксировать конкретное издание и исходную старофранцузскую орфографию, текстовые варианты как отдельные данные. Нельзя менять катрены под внешние события; обучаться на одной части и предсказывать заявленные грамматические отношения на отложенной части.
- **Трип-репорт:** использовать только при явном выборе исследователя; это личный текст, не публичный benchmark, и интерпретация не свидетельствует о физических причинах описанного.

G. С provenance DAG vs только слово (влияние на способность различать **истории операций**, а не только конечные слова).
