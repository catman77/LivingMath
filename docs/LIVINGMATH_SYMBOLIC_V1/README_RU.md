# LivingMath / White Star — SYMBOLIC_V1

**Передача кодовому агенту.** Комплект требований на расширение существующего MCP-сервера LivingMath, без переписывания работающего численного ядра Белой звезды.

**Цель:** сделать несвёрнутую символьную историю самостоятельным объектом исследования, а не превращать слово в 2D-координату до начала поиска; экспериментально проверить индукцию грамматических отношений, перенос между контекстами и связи с интерпретацией смысла.

**Состав:**

1. `01_TZ_SYMBOLIC_V1_RU.md` — ТЗ, область работ, архитектура, критерии сдачи, запреты.
2. `02_PROMPT_CODE_AGENT_RU.md` — готовый автономный промпт для кодового агента.
3. `03_API_AND_SEMANTICS_RU.md` — формальные семантики, минимальный MCP API, форматы событий и сертификатов.
4. `04_ACCEPTANCE_TESTS_RU.md` — тесты и контрольные эксперименты, включая слепые грамматики.
5. `05_BASELINES_AND_SOURCES_RU.md` — наблюдения из текущего прототипа и теоретическая мотивация.
6. `fixtures/symbolic_cases.json` — проверяемые примеры, коллизии, метаморфные преобразования.
7. `checks/check_fixtures.py` — исполнимая проверка математических свойств фикстур без сервера и сторонних пакетов.

**Порядок работы:** сначала агент изучает текущий репозиторий и сохраняет существующие границы; затем реализует дополнительный режим `symbolic_v1`, выполняет тесты и лишь после этого сравнивает грамматические гипотезы с контролями. Никакого нового универсального фреймворка, другого языка программирования, переписывания White Star, новых физических утверждений и фиктивного выигрыша в креативности.

## Подтверждённая исходная среда на 2026-11-05

- MCP `SUTI-Bridge-LivingMath`, `v0.3.0-developer-preview`, `white_star_status=READY`.
- Существующие профили Белой звезды: `base_v1`, `cj_v1`.
- Исходный интерфейс `white_star_explore` принимает 3–64 «concepts» с целочисленными координатами размерности **ровно 2**; возможны `white_star_inspect`, `white_star_replay`, `white_star_record_interpretation`, `white_star_validate_model`.
- Лимит `steps` 1–4096; отдельные лимиты по запросу, памяти и времени; подробности см. runtime status — агент обязан перепроверить их перед реализацией.
- Исторические исходные запуски сохранены в проекте `whitestar_dialog_test`; новый режим должен иметь отдельные `run_id`/схему и не изменять их артефакты.
- `execution_permission=false` в статусе относится к специальным разрешениям исполнения, но успешные sandbox-вычисления White Star уже выполнялись; не подменять эти два факта.

## Критерий успеха

Успех — **не** «все метрики стали больше». Успех — система различает структурно неэквивалентные слова, сохраняет заявленные эквивалентности при допустимых преобразованиях, предъявляет воспроизводимые свидетельства, переносит выявленные грамматические закономерности на скрытые примеры **лучше оговорённых простых baseline**, и не прячет смысловые подсказки в энкодере.

Если последний пункт не достигнут, результат может быть ценным инженерно, но нельзя называть его открытием семантики.
