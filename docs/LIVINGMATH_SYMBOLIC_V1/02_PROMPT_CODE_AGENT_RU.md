# Промпт кодовому агенту — применить ТЗ `SYMBOLIC_V1`

Ты работаешь **в существующем репозитории MCP LivingMath / SUTI-Bridge-LivingMath**, а не создаёшь новый проект. Пользователь разрешает доработать код по приложенному ТЗ и провести локальные тесты. Не спрашивай подтверждения для обычных неразрушающих изменений в ветке разработки. Не меняй продакшн-разрешения, секреты, endpoint авторизации, сеть или чужие данные.

## Задача

Реализуй **новый, совместимый экспериментальный режим `symbolic_v1`** для Белой звезды: несвёрнутые символьные истории как неизменяемые состояния, операции над словами, неврушающие КАД-наблюдения, ограниченный локальный поиск Удава, сравнение эквивалентностей, индукция проверяемых грамматических отношений и слепое тестирование. Полный объём и формальная семантика — в `01_TZ_SYMBOLIC_V1_RU.md`, `03_API_AND_SEMANTICS_RU.md`, `04_ACCEPTANCE_TESTS_RU.md`. Выполнить P0 и P1; если конкретный пункт объективно недостижим, описать блокер, а остальное довести до исполнимого результата.

## Порядок действий (реальное исполнение, не план вместо работы)

1. **Инспекция:** найди текущую White Star / CAD / Udav / Bridge / MCP имплементацию, тесты, frozen hashes, schemas и assurance limits. Составь краткую таблицу «файл/модуль → роль → что менять». Изучи последние code paths, а не подменяй существующий проект шаблоном из головы. Сохрани `UNCHANGED_SUPPLIED_CODE` и старые API. Не переписывай numerical kernel, когда достаточно добавить модуль.
2. **Минимальный вертикальный срез:** создай `SymbolicState` с полными токенами и DAG происхождения, операции `CONCAT`, `SPLIT`, `RENAME`, `REVERSE`, `SP_INV`, `REDUCE_SP`, `INSERT_CANCEL_PAIR`, один `CADObserver`, bounded поиск и новый MCP tool. Добейся реального запроса, run_id, inspect и replay.
3. **Расширь наблюдения:** буквальная идентичность, α-канонизация локальная/глобальная, соседство, контексты, композиция, S/P-свёртка, иерархические границы, observer-relative различимость. Нет смысла создавать новые «концепты» с 2D координатами из каждого слова: это старое ограничение.
4. **Интегрируй Удава** в качестве ограниченного исследователя локальных преобразований; сохраняй трассу кандидатов и свидетелей, не используйте exhaustive enumeration и эвристику, которая заранее знает ответ скрытого теста. Никакой LLM внутри kernel/score.
5. **Рабочая грамматическая индукция:** извлекай проверяемые контекстные/композиционные отношения из train, замораживай гипотезу, затем запускай sealed test. Сравни с простыми baseline на том же бюджете. Учитывай `UNDERDETERMINED`.
6. **Проверки:** запусти unit, property/metamorphic, интеграционные MCP, replay, backward-compat, а также синтетические грамматики. Не выдавай один успешный seed за статистическую репликацию.
7. **Артефакты:** создай `IMPLEMENTATION_REPORT_RU.md` с точными командами запуска, реальными результатами, логами и ссылками на изменённые файлы; отдельный `RCA_RU.md` при ошибках; `RESULTS.json` с версиями, digest, seed, baseline, CI status; data-only export и манифест. Если есть тесты, которые не удалось запустить, отметить `NOT_RUN` (не `PASS`).

## Не допускается

- Подмена формальной проверки объяснением словами.
- Притворяться, что богатые числовые координаты = полноценная грамматика.
- Редуцировать слово к q или 2D-вектору **как единственному состоянию**.
- Искать все возможные грамматики/трансформации без ограничения; строить orchestration stack, агент-самоисследователь, базы embeddings или собственный DSL предметной области.
- Заменять требование об изобретательности макетом, отчётом о намерениях, новыми «лестницами» или чистым рефакторингом.
- Изменять исходные baseline run-артефакты, преувеличивать эффект, выдавать статистический разрыв за смысл или за новые физические законы.
- Придумывать значения, статистику или заявления о выполнении тестов, если они не запущены.

## Как именно оценивается успех

1. `SSPP` и `SPSP`: одинаковый `q=0`, различный `literal_word`, обе истории доступны.
2. `ABBA` и `BAAB`: эквивалентны для изолированной α-канонизации; `AB|AB` и `AB|CD` не эквивалентны при **глобальной** канонизации.
3. Для `ab=SSPPSPSP` и `ba=SPSPSSPP` система различает истории, но не объявляет разными свёрнутые числа.
4. При всех тестируемых биективных переименованиях сохраняется α-класс; глобальная S↔P инверсия сохраняет q=0, но меняет знак ненулевого q; raw β₁ не обязаны совпадать.
5. `CONCAT` / `SPLIT` / `REDUCE_SP` / генеративная вставка компенсирующих пар корректны на большом наборе коротких случайных слов, включая ε.
6. Старые `white_star_explore`/`inspect`/`replay` не меняют контракт и frozen hashes.
7. Новая MCP схема, inspect/replay, лимиты, audit proof statuses работоспособны; negative cases возвращают типизированные ошибки.
8. Слепая индукция проверяется на скрытых примерах и сравнивается с unigram/bigram/context baseline, **даже если проиграет**.

## Формат финального ответа пользователю

Краткое резюме в 5 абзацах: (1) какой код изменён; (2) какие тесты реально прошли; (3) ключевой результат на S/P и скрытых грамматиках; (4) что не удалось и почему; (5) точные пути/артефакты. Никаких обещаний сделать потом. Если код ещё не готов, явно написать «НЕ ГОТОВО», а не «готово к production».

**Главный смысл:** не «построить ещё один движок», а проверить, можно ли на реальной символьной истории находить грамматические отношения, которые теряются при свёртке и при кодировании в 2D.
