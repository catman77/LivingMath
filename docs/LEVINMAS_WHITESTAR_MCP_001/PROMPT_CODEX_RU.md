# Задание кодовому агенту: LEVINMAS-WHITESTAR-MCP-001

Работай в **существующем репозитории подключённого LevinMAS / SUTI-Bridge-LivingMath**. Добавь отдельный режим Белой звезды и команды MCP; сохрани текущий режим SUTI. Пользователь хочет сравнивать два способа работы со смыслами через один сервер.

В архиве уже есть работающий код. **Не реализуй заново Белую звезду, CAD, Удава, численную сигнатуру или критерий выбора.** Возьми код из `code/` и общий вызываемый адаптер из `integration/white_star_adapter.py`. Это практическая интеграция готового вычислительного механизма.

Обязательно прочитай `TZ_RU.md`, `docs/CODE_MAP_RU.md`, `docs/COMPARISON_PROTOCOL_RU.md`, `docs/ACCEPTANCE_RU.md` и предлагаемые контракты в `contracts/`.

## Последовательность

1. Проверь текущий checkout, его AGENTS, версии, действительные MCP schemas, тесты, хранилище и способ регистрации инструментов. Сверь с `context/CONNECTED_STATUS_20261105.json`. Новые изменения в целевом репозитории имеют приоритет перед нашим историческим снимком: сохрани их и адаптируй точки интеграции.
2. В чистом временном каталоге воспроизведи `scripts/verify_bundle.py`. Сохрани результаты и реальные версии окружения. Не меняй frozen результаты, чтобы добиться зелёных тестов.
3. Перенеси вычислительный код без изменения алгоритма. Сохрани побайтовые SHA шести kernel-файлов. Изолируй импорты и native state в worker; обычный запрос не должен компилировать .so или блокировать event loop.
4. Зарегистрируй `white_star_status`, `white_star_explore`, `white_star_inspect`, `white_star_record_interpretation`, `white_star_validate_model` и `semantic_compare_runs`. Это предлагаемые НОВЫЕ команды; старые 55 не переименовывать и не переназначать. Если имя уже занято новой версией сервера, согласуй совместимый контракт в коде и документируй фактическое имя.
5. Прими произвольный текст через явную LLM-разметку `llm-white-star-concepts/1`; проверь источниковые байты и цитаты; сохрани общий semantic snapshot и отдельную геометрическую проекцию. LLM в этом режиме — вызывающий клиент, отдельный серверный модельный сервис не нужен.
6. Добавь append-only run journal, request-key идемпотентность, постраничный inspect, приватный экспорт и воспроизведение без LLM. Каждый run имеет независимое native state. `snapshot()` в исходном API — сводка, не восстановимый checkpoint.
7. Подключи существующий semantic bridge/SUTI к **тому же сохранённому входу** через добавочный ingress, если такого входа ещё нет. При невозможности принять frozen snapshot верни `UNMATCHED_INPUT` / `SUTI_ADAPTER_UNAVAILABLE`, не симулируй второй движок. Обязательный итог интеграции — реально работающий matched-input путь; недоступность означает PARTIAL, а не готовое сравнение.
8. Вынеси три семейства рациональных матричных проверок из демонстрационных M1/M2/M3 в типизированный адаптер; сохрани старые фикстуры и проверки. Отдели происхождение гипотезы от проверки конкретной матрицы. Остальные формальные системы возвращают `UNSUPPORTED_MODEL`.
9. Проведи регрессию исходного сервера и реальный MCP smoke через его транспорт. Получи результаты обоих режимов на Блоке и на втором входе; сравнение не обязано выявить победителя. Сохрани реальные вызовы/ответы, версии и затраты каждого режима.
10. Подготовь релизный пакет, точные команды запуска/обновления/отката и отчёт о фактически проверенном окружении. Если внедрение в целевую среду входит в предоставленный агенту доступ и поручение, доведи его до проверки подключения и реальных вызовов. Локальные тесты не выдавай за состоявшийся production deploy.

## Не менять смысл задачи

- Старый выбор Удава остаётся прежним. Нет полного перебора интерпретаций, нового TSP-решателя, semantic reward, reranking или подбора удачного seed.
- Подготовка конечного атласа допустима; оценка всех карт на каждом шаге вместо k кандидатов — нет.
- Проекции могут быть неортогональными. Профиль `cj_v1` — существующее расширение 003; нельзя заменить его произвольным новым генератором.
- Все aliases одной численной карты сохраняются. Это несколько подписей одной проекции, а не дополнительные открытия.
- Адресованная цитата подтверждает байты. Она не подтверждает автоматически интерпретацию.
- Не запускай полный reachability audit в горячем пути и не используй его как оракул выбора.
- Не переноси старый архив LevinMAS поверх свежего checkout; не запускай исторические freeze/annotation scripts как «универсальный парсер».
- Не прячь `SUTI_native_runtime=NOT_EXECUTED`, не выдавай bridge за нативный SUTI и не меняй unrelated release/physical-execution статусы.
- Сравнение считает литературную ценность отдельно от численной новизны. Никакого требования «Белая звезда должна победить».
- Существующий MCP framework сохраняется; не мигрируй SDK ради этой задачи.
- Новая инфраструктура ограничивается адаптерами, журналом, контрактами, проверками и подключением. Не строй новый исследовательский фреймворк.
