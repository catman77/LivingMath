## Известные места доработки

1. **Импорты.** Исходники используют короткие имена `source`, `cad`, `bridge` и правку sys.path. Новый демонстрационный адаптер также так устроен. Для сервиса использовать отдельный worker-процесс с фиксированным PYTHONPATH; не засорять глобальные модули основного сервера. Перепаковка в нормальные Python namespaces допустима отдельным механическим изменением обёрток с тестом эквивалентности, но шесть frozen kernel-файлов сохранять.
2. **Сборка.** Текущий build_native() лениво собирает .so в каталоге исходников. На production вызвать его на build/startup и проверить наличие совместимого бинарника до объявления ready. Никакой shell-команды от MCP-клиента.
3. **Лимиты.** bridge.validate допускает до 64 понятий, а expanded atlas ограничен 4096 уникальными матрицами. Проверять фактическое число после дедупликации. Для 45 понятий верхняя оценка 2n(n−1)=3960; для 46 возможно 4140 — это отдельный отрицательный тест. Не урезать атлас молча.
4. **Текст.** Старый decoder_packet содержит формулировку «шесть кадров», а freeze_input — разметку Блока. Новый адаптер строит динамический packet из фактически выбранных кадров и принимает внешний encoding.
5. **Формальные проверки.** verify_transfers() принимает ровно M1/M2/M3 и связывает их с F05/F03/F06; M3 жёстко знает street/lamp/pharmacy. Это проверенные демонстрации, не универсальный валидатор. Новому API нужны семейство, матрицы, source/run/frame refs и явные обязательства.
6. **Состояние.** Каждый FastWhiteStarSource владеет отдельным состоянием. Не делить instance между запросами. snapshot() не содержит полного состояния Удава. Для v1 воспроизводить запуск заново по входу и seed; continuation/session steering не входят в обязательный MCP минимум.
7. **Производительность.** Старое измерение ~4 мс относится к вычислительной части на конкретной машине, без импорта, сборки, LLM и полного аудита. Не обещать такую же end-to-end задержку удалённого MCP.
8. **Эталон.** reference_replay() временно меняет глобальный CHARTS и требует coprime(11,N); это диагностическая функция для замороженного N=354. Не вызывать её из конкурентного production path. Native умеет корректировать stride для других N.
9. **TSP.** В литературном опыте нет задачи минимизации длины маршрута; основной TSP-решатель не вызывается. Не добавлять искусственную TSP-цель только из-за исторического названия Удава.
10. **Локальный адаптер.** Это рабочая интеграционная заготовка, не серверный security boundary. Перед его вызовом нужны JSON Schema, права проекта, durable journal, worker limits и error mapping. Формирование common_snapshot ещё не означает, что текущий SUTI его принимает.

## Историческая совместимость

В `context/LM_SUTI_SEMANTIC_BRIDGE_001_TZ_PROMPT.zip` находится ранее выданное задание на SemanticFrame/RevisionEdge/assurance. Оно приложено для согласования имён и повторного использования реализованных частей. Наличие ТЗ не доказывает наличие его реализации. Эта поставка не требует повторного выполнения всего того исследования и не запускает ещё шесть литературных чтений. Если semantic bridge уже реализован — подключиться к нему; если нет — добавить необходимый минимальный ingress/report для двух режимов.

`context/CONNECTED_*` — снимки чтения действующего endpoint. Их надо заново сверить в целевом checkout; они не содержат исходники текущего сервера.
