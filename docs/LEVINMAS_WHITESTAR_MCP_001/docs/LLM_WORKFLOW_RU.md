# Как LLM использует два режима после интеграции

Это предлагаемый будущий цикл MCP. Сейчас приложен локальный численный адаптер; серверные команды должны быть реализованы исполнителем.

1. Прочитать bridge_system_status и white_star_status. Увидеть фактические backend, limits и доступные режимы.
2. Для нового текста подготовить полный encoding по fixtures/original_request.json: байты, цитаты, понятия, две оси, координаты и объяснения. Не копировать образы Блока в другой текст.
3. Вызвать white_star_explore(project, request_key, request). Сервер сохраняет общий snapshot и возвращает run_id. Готовый tools/call пример: fixtures/mcp_blok_call.json.
4. При необходимости прочитать white_star_inspect(view="trace"/"frames"/"decoder"). Отдельные численные aliases — альтернативные подписи, а не дополнительные прогоны.
5. На основании decoder packet сформулировать прочтения. В каждом отделить цитаты, предложенные связи, собственные добавления, альтернативы и ограничения.
6. Вызвать white_star_record_interpretation с этими текстами и frame refs. Получить reading/claim refs. Проверка записи подтверждает происхождение и адреса; смысловой статус остаётся INTERPRETATION.
7. Если нужен формальный перенос, сформировать один поддержанный rational model, явно перечислить предпосылки и сослаться на сохранённый claim. Вызвать white_star_validate_model. CHECKED_INSTANCE означает проверку математического экземпляра, не доказательство художественного толкования.
8. Для сравнения передать тот же frozen common snapshot в реальный SUTI ingress. Сохранить его run и фактическое происхождение; если существующий SUTI parser заново извлёк понятия, показать UNMATCHED_INPUT.
9. Вызвать semantic_compare_runs на двух сохранённых run refs. Прочитать техническую сопоставимость и результаты, затем сделать явно атрибутированное сравнительное прочтение.

Обычный запрос «используй Белую звезду» не обязан запускать SUTI, валидатор формальной модели и comparison. Эти действия отдельные и выбираются по исследовательской задаче. Все промежуточные данные доступны для inspection, но исследователю можно показать краткий результат и ссылки на полный журнал.
