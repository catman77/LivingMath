# Сравнение LevinMAS/SUTI и LevinMAS/Белая звезда

## Что сравниваем

Один художественный источник, один замороженный набор понятий и исходных связей, два механизма преобразования, один способ предъявления результатов. Цель — увидеть различия получаемых трактовок и стоимость работы. Превосходство одного режима не является критерием приёмки.

### Общий вход

Сохранить UTF-8 байты, SHA256, права, идентификаторы и цитаты понятий, source_relations, неопределённости, происхождение кодирования. Формат `levinmas-semantic-input/1` является **новым предлагаемым контрактом**; его создаёт common_snapshot() в готовой заготовке. Он не является уже существующей схемой SUTI.

Геометрия Белой звезды хранится отдельно: axes, координаты, объяснения, atlas_profile и protocol. Это дополнительные модельные предпосылки, не свойства текста. Их нельзя приписать исходному произведению или скрыть в итоговом сравнении. SUTI-проекция также имеет версию и список полей, которые использует, добавляет или теряет.

Для MATCHED_INPUT обе ветви реально получают один и тот же snapshot digest. Повторный LLM-extraction исходного текста внутри одной ветви делает вход другим. Нужен путь replay/ingress frozen snapshot или честный статус UNMATCHED_INPUT. Сам по себе одинаковый source SHA недостаточен.

## Два допустимых режима опыта

| Режим | Вход | Что позволяет заключить |
|---|---|---|
| MATCHED_INPUT | Один source/semantic snapshot; разные объявленные backend projections | Различия конкретных механизмов при этих фиксированных предпосылках |
| END_TO_END | Один текст; каждый текущий pipeline делает свой extraction | Различия полных pipeline; влияние encoder и backend не разделено |

Если SUTI snapshot ingress ещё не реализован, END_TO_END можно выполнить как дополнительную диагностику, но обязательный matched-input пункт остаётся незавершённым. Если реальный SUTI runtime не использовался, название backend в отчёте — действительный bridge/observer/DAV pipeline, с сохранением поля SUTI_native_runtime.

## Один короткий цикл

1. LLM кодирует текст один раз, явно объясняя координаты. Сохраняются точный JSON, сырой ответ/receipt при наличии и версия инструкции; это не gold truth.
2. На том же snapshot выполняются оба режима. White Star: default seed=42, steps=64, k=3, frame_size=3, первые 6 полных кадров. SUTI: существующий bounded protocol с отдельно зафиксированным бюджетом и версией.
3. На вход decoder передаётся общий текст и результаты соответствующего режима. Одинаковы модель, инструкция, число слотов интерпретаций и доступ к источнику. Невозможные/пустые слоты остаются пустыми с причиной.
4. Первый полученный валидный output сохраняется. Не выбирать лучшие seed, не повторять до красивого результата; неудачи остаются в журнале.
5. Сравнение учитывает цитаты, используемые мотивы, новые связи, альтернативы и сомнения. Число разных перефразировок не считается числом независимых смыслов автоматически.
6. Для оценки художественных свойств дать человеку либо отдельному явно обозначенному оценщику анонимизированные результаты; порядок A/B менять заранее по фиксированному правилу. Автоматическая оценка остаётся оценкой LLM, не математическим сертификатом.

### Общая инструкция decoder

«На основе данного текста и предложенных связей сформулируй до K различимых прочтений. Сохрани порядок предоставленных кадров. Для каждого укажи буквальные опоры с source anchors, предложенные связи, добавленные образы/предпосылки, альтернативу и ограничение. Несовместимые aliases сохрани как альтернативы. Не объявляй высказывания персонажа фактами о мире. Не приписывай численным весам вероятность или истинность. При нехватке данных отметь отсутствие результата».

Инструкции адаптации raw result каждого backend в decoder packet версионируются отдельно. Переименование полей допустимо; добавление новых смысловых связей детерминированным formatter запрещено. Если packet требует LLM-перевода из SUTI, это отдельный model call со своими затратами и статусом.

## Отчёт

Обязательные поля:

- source_sha256, common_snapshot_sha256, encoding/projection digest, engine/version/backend_status;
- requested/effective budgets, число фактических LLM calls/tokens (null, если недоступно), numeric projections только для White Star;
- cold start, warm numeric time, persistence/serialization, MCP round trip, LLM latency раздельно;
- сколько выходных кадров/прочтений фактически сформировано;
- корректность source anchors; semantic fidelity отдельно;
- цитированные и добавленные мотивы, сопоставление трактовок, сохраняемые альтернативы;
- все ограничения проекции и случаи отказа.

**192 CAD-проекции не эквивалентны 192 шагам SUTI/DAV.** Сравнивать время, затраты, результаты и ограничения; native counters разных алгоритмов показывать рядом без вымышленного равенства единиц. Координатные признаки у White Star и внутренние признаки SUTI различны по построению.

Числа 52/58/720 относятся к определённому качественному readout и атласу. Это не количество всех смыслов и не рейтинг литературной ценности. Теорема о возможных режимах не обещает, что Удав посетит каждый из них за 64 шага.

## Минимальный опыт при приёмке

Два входа из fixtures: Блок и оригинальный короткий текст. На каждом — сохранённый общий вход и реальные результаты двух режимов. Результаты нового текста в этой поставке проверяют численный перенос адаптера; они не являются уже выполненным живым сравнением SUTI с Белой звездой.
