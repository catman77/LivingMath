## 2. Неизменяемый вычислительный механизм

Операция пар:
`(a,b) ⊗ (c,d) = (ac+bd, ad+bc)`.
Для `Z_s=(s,s)`: `q⊗Z_0=Z_0`, `q⊗Z_1=Z_(a+b)`.
Белая звезда выдаёт ленивую последовательность свидетелей `q=(a,b)∈N²` существующим алгоритмом. CAD применяет целочисленные невырожденные матрицы 2×2, включая неортогональные. Удав выбирает из k кандидатов по прежней сигнатуре/структурной новизне/редкости со старым правилом разрешения равенства.

**Запрещено менять:** orbit, scheduler, генерацию кандидатов, порядок/формулу score, tie-breaking, обновление observation graph, арифметические signatures. Шесть kernel-файлов из CODE_MAP сохраняются побайтово. Если обнаружен реальный kernel bug — предъявить отдельный воспроизводимый дефект; не исправлять его незаметно под видом MCP-обвязки.

Профили:
- base_v1 — исходные упорядоченные пары независимых векторов понятий;
- cj_v1 — те же C и C·J, где `J=[[0,-1],[1,0]]`; матрицы C·J равны `[b,-a,d,-c]`.

При численном совпадении матриц объединяется геометрия, сохраняются **все** семантические aliases. Нет выбора удобной подписи. Atlas compile перечисляет конечные карты; это не перебор интерпретаций и не оценка всех карт на каждом свидетеле.

Readout остаётся фиксированным:
`xy>0 → ALIGN`, `xy<0 → TENSION`, `xy=0 → UNRESOLVED`;
доминирование определяется сравнением |x| и |y|, веса сокращаются по gcd. Нулевой свидетель не имеет направления и исключается из смысловых кадров. Это конвенции интерфейса, не вероятности, не логическая истинность и не скрытая оценка качества литературы.

Полный reachability audit — только offline/diagnostic. Не вызывать exact_field, old_reachability, mutation suites или 11 повторов timing из обработчика explore. В рабочем запросе выполнить ровно указанный бюджет один раз.

## 4. Контракт входа и ответственность LLM

LLM-клиент читает исходный текст, формирует `llm-white-star-concepts/1`, получает численные предложения и переводит их в образы/формальные гипотезы. Серверный LLM для White Star v1 не требуется. Работающий hosted proposer текущего SUTI сохраняется как есть; его вызовы учитывать отдельно.

Вход encoding включает:
- source: точный UTF-8 text, sha256, author/title, права на хранение/экспорт;
- concepts: уникальные id, label, точные evidence, coordinates=[int,int], encoding_rationale;
- axes: ровно две явно названные оси;
- source_relations и uncertainties;
- provenance, включая автора/модель/инструкцию/режим FIXTURE или LLM, если эти сведения доступны;
- protocol: seed, steps, candidates_per_step, frame_size, decode_first_frames.

Byte spans — полуинтервалы [byte_start,byte_end) **в UTF-8**, line — 1-based. Никакой Unicode-нормализации, исправления ё/е, кавычек, переводов строк или текста цитаты после freeze. Проверка source SHA/byte slice обязательна. Модельное присвоение прав или цитаты не считается независимо проверенным фактом об авторстве; сервер связывает их с источником по своей действующей политике.

Строгая JSON Schema перед native вызовом плюс смысловые проверки ссылок, цитат, непустых/различных координат, сингулярности и размеров. Boolean не принимать как integer. Типизированные поля не восстанавливать эвристически и не исправлять за LLM; вернуть адресную ошибку.

Предлагаемый request — contracts/white_star_request.schema.json; полные валидные examples — fixtures/. Не принимайте произвольный код, выражения eval, пути к модулям, shell commands или загрузку shared libraries от пользователя.

### Общий snapshot

common_snapshot() выделяет source, concepts без координат, source_relations и uncertainties. Сохранить этот объект до запуска обеих ветвей. Отдельно сохранить координаты, оси, выбранный профиль и объяснения как White Star projection. Порядок образов/связей не стирать сортировкой списков.

Canonical JSON для digest: UTF-8, ensure_ascii=False, sort_keys=True, separators=(',',':'), allow_nan=False, без Unicode normalization. Эта канонизация локально определена контрактом; не называть её RFC 8785. SHA исходного текста считается непосредственно от его UTF-8 байтов.

## 5. Новые MCP-команды

Названия ниже — **добавляемые**, не уже доступные. Сохранить существующую регистрацию и транспорт сервера. Не менять SDK/framework без самостоятельной необходимости.

| Команда | Параметры | Результат |
|---|---|---|
| white_star_status | пустой объект | версия, readiness native, limits, profiles, hash ядра; режимы SUTI/WhiteStar и фактический backend |
| white_star_explore | project, request_key, request | durable run_id, summary, selected frames, decoder packet либо ссылка на страницы, digests |
| white_star_inspect | project, run_id, view, offset, limit | input/summary/atlas/trace/frames/decoder/report/export; без нового поиска |
| white_star_record_interpretation | project, run_id, request_key, readings | сохранённые LLM-тексты с frame/anchor refs и статусом INTERPRETATION |
| white_star_validate_model | project, run_id, proposal | проверка одного из трёх поддержанных матричных семейств и адресной связи с гипотезой |
| semantic_compare_runs | project, left, right, protocol | сравнение двух сохранённых run refs; MATCHED_INPUT или явное ограничение сопоставимости |

record_interpretation не вызывает модель: LLM-клиент передаёт уже полученный ответ. Проверяются frame refs, byte anchors и provenance; формальная корректность записи не означает смысловую верность. Создаются immutable reading/claim refs, пригодные для validate_model и comparison. Для (project, run_id, request_key) действует тот же conflict/idempotency контракт. Повторный validate_model с тем же run/proposal digest возвращает тот же check receipt.

Новые команды описать так, чтобы LLM понимала полный цикл: encode → explore → inspect → decode → record_interpretation; формальный перенос → validate_model. Примеры на русском вложить в справку без жёсткого привязывания к стихотворению Блока.

white_star_status/inspect/semantic_compare_runs читают данные. explore, record_interpretation и validate_model сохраняют run/check records: их нельзя помечать readOnlyHint=true. Все вычисления остаются символными; physical execution не включать. Наличие инструмента не должно менять текущие права пользователя на проекты.

MCP результат — structuredContent с версионированной схемой и компактный совместимый text block. Для доменных ошибок использовать стандартный tool result isError=true, типизированный code, message, field_path и request/run id, если он существует. Для успешно выполненной проверки, обнаружившей математический контрпример, вернуть обычный результат REJECTED с witness: это содержательный исход проверки, а не сломанный транспорт. Поддержать outputSchema на фактическом SDK либо явно документировать совместимое отображение.

Коды: INVALID_INPUT, SOURCE_MISMATCH, EVIDENCE_MISMATCH, ATLAS_LIMIT_EXCEEDED, INPUT_TOO_LARGE, ENGINE_UNAVAILABLE, WORKER_LIMIT, REQUEST_CONFLICT, NOT_FOUND, SUTI_ADAPTER_UNAVAILABLE. UNSUPPORTED_MODEL — честный результат для неподдержанного формального языка.

Официальная справка MCP Tools: https://modelcontextprotocol.io/specification/2025-11-25/server/tools (просмотрена 2026-11-05). Новые инструменты должны появиться при реальном tools/list; прямой Python-вызов не заменяет эту проверку.

## 6. Хранилище, идемпотентность и воспроизведение

Использовать существующее project-scoped хранилище и export facade. Минимальный run record:

- schema/version, run_id, project, request_key, engine и статус;
- source/common_snapshot/encoding/protocol hashes, версии адаптеров и ядра;
- requested/effective budgets и причины отклонения;
- exact input, atlas/aliases, полный trace, readouts, frames, decoder packet;
- фактические временные показатели, native counters и model receipts, если есть;
- parent/check/interpretation refs, ошибки и незавершённые состояния.

Нельзя ссылаться только на внутренний путь к временному файлу. Сохранённый результат должен переживать restart. Atomic transition RUNNING→COMPLETED после записи всего результата; ошибка/таймаут сохраняются явно. При падении процесса зависшие RUNNING переводятся в INTERRUPTED; не выдавать их за завершённые.

Ключ идемпотентности — (project, request_key). Тот же полный digest возвращает тот же run и не запускает повторный поиск; тот же ключ с другим digest даёт REQUEST_CONFLICT. Защитить конкурентную вставку транзакцией/unique constraint. Историю не переписывать.

MCP-сессия и вычислительный run независимы. Один instance FastWhiteStarSource — один job. Для v1 достаточно законченных bounded запусков; никакого обещания продолжения из snapshot(), поскольку это только счётчики. Replay пересчитывает поиск по сохранённому input/protocol и сверяет logical digest. Он не вызывает LLM и не перегенерирует уже сохранённую прозу.

Постраничный inspect возвращает целые записи, offset/next_offset и полный total; страницы стабильны для immutable run. По умолчанию limit=64, максимум=128 и до 256 KiB сериализованного ответа; при более крупной записи использовать существующий artifact/download механизм с server-owned refs. Нельзя silently truncate JSON. Source rights и project access проверять тем же способом, что для остальных артефактов сервера.

## 7. Ресурсы и время

Предлагаемые White Star v1 limits (отдельный профиль, прежние SUTI limits не менять):
- UTF-8 text до 48000 bytes; полный request до 256 KiB;
- 3..64 понятий, вектор ненулевой, различные векторы, |coordinate|≤10^6;
- actual unique charts≤4096; достаточно карт для k;
- signed 32-bit seed; steps 1..4096, default 64; k 1..16, default 3;
- frame_size 1..steps, default 3; decode_first_frames 1..64, default 6;
- worker CPU≤5s, wall≤6s для численного job; память≤512 MiB после измерения cold imports на целевой системе;
- внутренний result≤32 MiB; MCP response≤256 KiB;
- worker pool bounded: default 2 concurrent jobs и очередь 16 либо более строгие общие квоты сервера.

Лимиты явно возвращать в status. При несовместимости окружения с установленной памятью/бюджетом — исправить окружение или документированно изменить профиль, не скрывать отказ и не урезать вход. Не применять численные six-second limits к старому hosted LLM stage.

Подготовить native библиотеку при build/startup, lazy build из запроса выключить организацией запуска worker. Прогреть worker и измерить import/native load отдельно. Не переносить наличие pandas из reference импорта в объяснение пользователю; оптимизация зависимостей возможна после корректного переноса, с эквивалентностью и без изменения kernel.

Замерить не более 11 повторов одного frozen run: медиана и диапазон, cold/warm, serialization, journal и транспорт отдельно. Долгий performance benchmark не нужен. Сравнивать локальный adapter с обёрнутым worker на одной машине. Сложную оптимизацию отложить, если профиль не выявил конкретного узкого места.

## 8. Формальный перенос

Отделить:
1. Исходный текст и его адреса.
2. LLM-интерпретацию и добавленные предпосылки.
3. LLM-предложение модели в целевой области.
4. Проверяемые отношения **внутри** этой модели.

Готовые функции rational matrix operations переиспользовать. Новый API принимает семейство, rational matrices, выбранные утверждения и provenance run/frame/reading refs. Ограничить размер 1..8, bit length числителя/знаменателя≤256, denominator≠0; никаких float или символьного eval. Источниковая запись/цитата должна быть зарегистрирована и сверена; сам удачный hash не подтверждает перенос смысла.

| family | Обязательства конкретной проверки |
|---|---|
| observation_invariant | A квадратна, C/x согласованы; CA=C; для примера скрытого изменения Ax≠x и CAx=Cx |
| control_invariant | wA=w, wB=0; x'=Ax+Bu; если заявлено частичное улучшение — Cx≠0, Cx'=0 и wx≠0 |
| cyclic_order | три совместимых квадратных оператора U,L,P; P обратим; M0=PLU, M1=LUP, M1=P⁻¹M0P; если заявлено различие действия — M0x≠M1x |

Контрмодель к усилению утверждения передаётся явно и проверяется отдельно. Для первой реализации cyclic_order можно ограничить размер 2×2, соответствующий готовому inverse2(), и вернуть UNSUPPORTED_MODEL при другом размере; status обязан объявлять этот предел. Имена операторов не привязаны к street/lamp/pharmacy; соответствие последовательностям источника проверяется адресами или маркируется как дополнительное LLM-допущение.

Статусы: CHECKED_INSTANCE, REJECTED с конкретным нарушенным обязательством, UNSUPPORTED_MODEL. source_binding, translation_fidelity и physical_validity — отдельные поля. Не присваивать всей интерпретации статус PROVED_FORMAL/VERIFIED из-за равенства матриц.

Не включать новый CAS, химический валидатор, физический симулятор или универсальный theorem prover. Развитие формальных языков — следующая задача. Сохранённые три переноса 003 взяты из чтений F05/F03/F06 опыта 001; не приписывать их новой траектории 003.
