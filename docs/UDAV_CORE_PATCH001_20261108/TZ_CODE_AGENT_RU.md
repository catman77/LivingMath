# UDAV–CORE–PATCH001 — минимальные подтверждённые исправления поиска

**Дата постановки:** 2026-11-08.  **Заказчик:** исследовательский проект «Реальная магия» / LivingMath.  **Исполнитель:** кодовый агент.  **Назначение:** сделать пригодную для следующих исследований версию MCP, исправив проверенные недостатки поиска **без переноса научного мышления внутрь Удава**.

## 0. Установленные факты и принципиальная граница

Исследовательская архитектура: **LLM задаёт смысловые гипотезы и интерпретирует результаты → Удав выбирает/расширяет структурные возможности → CAT/CAD даёт наблюдения → Белая звезда порождает синтетический процесс**. Физическая модель и LLM остаются внешними к этим поисковым ядрам; возвращаемые наблюдения не объявляются доказательствами исходной семантики.

Никаких DSL генерации теорий, `MAIN/SHADOW` банков, `XOR3`-синтеза, скрытых oracle, новых natural-language декодеров, эвристик «истинности», встроенной LLM и API-ключей в этом патче. Эксперименты UDAV-NEXT 004–007 были полезными лабораторными контрольными моделями, но **не спецификацией production-функциональности**.

Проверенные технические границы (обязательно различать):

- **Symbolic V1** — `src/lm_suti_assurance/symbolic/search.py`: `tried` только `(node,operator)`, параметры повторяются; невыбранные результаты `SPLIT` не получают нормальной очереди расширения; fallback только после локальной стагнации. На live-сервере для `abcabcab`: 80/144 шагов выполнялись на ε при наличии ещё не расширенных содержательных узлов; 374/432 `SPLIT` попыток — дубликаты. Это подлежит починке.
- **Symbolic Pareto**: `literal`/`composition` производят практически уникальные хеши наблюдений, поэтому 96/96 локальных Pareto-фронтов не отфильтровали ничего; это недостаток **конкретного метрика/планировщика**, не дефект законов CAT или native.
- **Numerical White Star/CAT/UDAV**: опубликованный native C++ точно воспроизводится на тестовых синтетических трассах; 8-битный `ReversibleUDAV` — историческая реконструкция clock, native-выбор по четырём численным критериям корректен. Сигнатура `sigma` не включает источник пары; при `w=(1,1)` 112 CAT-карт дают 48 сигнатур. При этом исходные полные карты **сохраняются** в атласе, то есть это потеря различений при **оценке**, не потеря хранения данных.
- Установлен частный выигрыш добавления идентичности исследуемой CAT-пары как *опционального* tie-breaker после первичной графовой новизны; на 30 seed покрытие пар 16.90→22.63. Это **не** доказательство универсального критерия научной интересности; поэтому менять legacy score по умолчанию запрещено.

## 2. P0 — Symbolic: честное расширение сохранённого фронтира (обязательное)

Добавить новую **opt-in** поисковую стратегию, например `frontier_argument_coverage_v1`, сохранив побайтно прежнее поведение `local_structural_novelty` и `random_local` для исторических запросов и replay. Расширение enum/search schema — только назад совместимое; существующие поля/поля provenance и пределы сохраняются.

### 2.1. Единица исследовательской работы

Не `(node,operator)`, а **(node_id, operator, parameter_key)**. Для `SPLIT` параметр — точная целочисленная позиция `0..len(word)`; для `INSERT_CANCEL_PAIR` — `(position,kind)`; для `CONCAT` — целевой родитель из разрешённого конечного набора. Для `RENAME`, `SUBSTITUTE` и операций с многими параметрами нельзя делать вид, что единственная clock-sampled проба перебрала семейство: фиксировать `ARGUMENT_FAMILY_PARTIAL` и sampled budget. Параметры нормализуются и хешируются в каноническом порядке, дедуплицируются **до** expensive `apply`.

Генерировать дескрипторы лениво с ограниченными cursor, а не создавать произведение `max_nodes × all parameters` в памяти. За один вызов `apply` и каждый его выход списывать корректные бюджетные единицы. Не запускать полный перебор экспоненциальных параметров.

### 2.2. Фронтир состояний и multi-output

Оба результата `SPLIT` и все результаты прочих multi-output операций сохранять с DAG parent / operator / parameter / output_part. **Каждый сохранённый допустимый результат** может стать отдельным родителем будущих операций. Справедливое планирование по *неисследованным* `(node,op,param)`; не продолжать бесконечно ε-путь, пока есть доступный нетривиальный work-item. При этом ε **не удалять** и не объявлять математически бесполезным во всех задачах: в конкретном `SPLIT` только исчерпать его `position=0` один раз, после чего переходить к сохранённым неисследованным альтернативам.

`history_identity="word"|"provenance"` должен сохранять обе договорённые семантики. В режиме `provenance` одинаковое слово с разными историями — разные nodes. Не усекать source spans и границы; DAG и replay остаются проверяемыми.

### 2.3. Стабильность и диагностика

Выбирать work-item детерминированно по seed и **канонически отсортированному** набору разрешённых операторов/параметров, чтобы простая перестановка массива operators не меняла план при одинаковом наборе. Сэмплер аргументов не должен смешивать state scheduling и операторный clock одной общей неразделённой последовательностью, если это вызывает систематическую недоступность операторов; разделить потоки seed/state/operator/arg или использовать стабильные hash ranks.

Сохранять `proposed`, `applied`, `new_outputs`, `duplicates`, `forbidden`, `resource_limited`, `parent_revisits`, `frontier_remaining`, `parameter_coverage`, `chosen_output_part`, `unexpanded_nontrivial`, `budget_remaining`, `halt_reason`, статус `PARTIAL_PARAMETER_COVERAGE`. Всегда отмечать неполноту, даже если исчерпаны все видимые `(node,operator)`; не писать `GLOBAL_EXHAUSTION_PROVED` без доказательства по заявленной конечной алгебре.

Запрещается **подменить исправление** увеличением `max_steps`/`max_nodes`, запретом `SPLIT` на ε или сортировкой кандидатов по известной oracle-цели.

## 3. P1 — прозрачное представление наблюдательной новизны (обязательная диагностика)

В новой стратегии нельзя использовать один SHA каждой полной буквальной строки как доказательство исследовательской новизны. Сохранять `literal`/`composition` как **сырые наблюдения**, но отдельно считать структурные quotient/witness classes (`alpha_pattern`, `adjacency`, `sp_reduce`, композиционные свойства) с явно заданной областью применимости. Не отождествлять различия source/history, если они релевантны `history_identity`.

В новом результате вернуть две ортогональные метрики: `new_raw_observation` и `new_structural_class`, плюс `pareto_filtered_count`. Если выбранный набор наблюдателей не определяет нетривиальную структуру, возвращать `STRUCTURAL_NOVELTY_UNDEFINED` и использовать честное покрытие фронтира, а не фиктивную семантическую оценку.

Нельзя превращать этот режим в grammar induction, NL→FOL или LLM replacement. Его задача — удерживать и эффективно обследовать структурно различные CAT-варианты.

## 4. P2 — численный CAT→Удав: opt-in устранение *частного* слепого пятна (обязательное, НО НЕ менять legacy по умолчанию)

Предоставить **отдельный opt-in** численный search/selection mode (новый tool или строго обратно совместимое поле с отдельной версией контракта) `cat_distinction_tiebreak_v1`:

1. Вход — source-bound CAT-атлас с полной матрицей, `view_id`, все `aliases` (могут быть неоднозначны), точные concept pair IDs и provenance; нормализовать идентичности по исходным IDs/адресам, не по хешам произвольного языка. Сигнатуру `sigma` и graph novelty не менять.
2. На каждом кандидате сохранять полную информацию об адресуемом CAT-различии; **при равном первичном графовом novelty** приоритет получает ещё не представленное различие, затем старый порядок (rarity signature → phase → view count → стабильная ничья). Это *измеримый policy*, а не универсальная теория интересности. Не выбирать кандидата с **меньшей** первичной novelty ради новой пары.
3. Для 1:1 пары добавлять `new_pair` из точных concept ID. При нескольких alias-парах не выбирать произвольную `aliases[0]`: хранить множество альтернатив, считать `ambiguous_aliases` отдельно, не маркировать все эти пары как точно исследованные без явного правила; допустимо fail-closed `DISTINCTION_AMBIGUOUS` и отказ от tie-break в таком случае.
4. **Корректное динамическое обновление памяти!** Нельзя просто переупорядочить исторические `candidate_scores`, потому что после нового выбора меняются graph/seen/used/phase следующего шага. Использовать отдельный вычислительный opt-in путь/worker или расширение native реализации с неизменным legacy; пересчитывать полную траекторию. Замороженный выбор на старом списке годится как диагностика, но НЕ выдаётся за production search.
5. Унаследовать те же ресурсные пределы, исходный witness sequence, исходный atlas, подтверждённый provenance, число k/steps, отсутствие LLM/network. Сохранять `selected_by`, `novelty_primary`, `distinction_key`, `seen_before`, `topology_score`, `reason_tie_break`, `candidate_list_sha`, `source_ref`.

Legacy (`white_star_explore` без явного нового режима) должен воспроизводить старые view, candidate_scores, outputs, old immutable receipt/replay **побайтно**, включая старый vendor C++ source/hash. Если невозможно реализовать альтернативу, не меняя эти свойства, отделить её в новом tool/worker и не перекомпилировать старый kernel от изменений.

**ЗАПРЕТ:** трактовать source_relations как установленные факты, делать смысловой rerank, передавать свободный текст LLM в численный scorer, менять WhiteStarOrbit, корректировать исторический 8-bit clock или навязывать всем пользователям new_pair.

## 5. P3 — исследовательский интерфейс без встроенной LLM (малый, необязательная оптимизация)

Поставить LLM-клиенту **данные**, не функцию «научного вывода»: краткий bounded summary просмотренных структур и проигнорированных различий, source-bound ссылки на полные CAT-карты/истории, проверяемый candidate audit. Возможный JSON request со структурными ограничениями должен проверяться существующим evaluator и не содержать генератора гипотез.

**G3 — аргументы/ветви/порядок:** unit и MCP тесты `SPLIT` для k=0,n и всех внутренних позиций; оба ребёнка могут быть расширены; `history_identity` word/provenance; `INSERT_CANCEL_PAIR` обе `SP|PS`; точная единственность attempted tuple. **G4 — наблюдатели:** тест против ложно-уникальных `literal`/`composition` SHA: `new_raw_obs` может расти при `new_structural_class=0`, и это не выдаётся за научное открытие. **G5 — numerical:** на 8-concept 112-chart quadratic CAT, seed23..52, `k=8, steps=24`, честный opt-in dynamic score должен обеспечить **среднее ≥21/28** разных *однозначных* пар и `primary_novelty` в каждом шаге не ниже максимума доступных candidates по старой основной оценке. Старый наблюдавшийся baseline =16.9 пар; ожидание исследовательского контроля =22.633. Важно: это известный корпус = regression, НЕ новый blind result. Дополнительно новые CAT-геометрии/seed с зафиксированной до начала рубрикой должны показать отсутствие деградации *primary* topology score, корректный replay, и не иметь silent alias mislabel.

**G6 — ресурсы:** не более прежних `max_steps`, `max_nodes`, `max_total_tokens`, `max_observations`, `worker_cpu_s`, `worker_wall_s`, `worker_memory_bytes`. CPU/стены/RSS по arm; budget halt = `PARTIAL/BOUND`, не ложный exhaustion. Тест при искусственно коротком лимите — явная неполнота и сохранение provenance.

**G7 — злоупотребления/ошибки:** чужой project, fake run/node, altered source SHA, изменённый payload с тем же request_key, невалидные аргументы, fake alias, deprecated provenance, подмена replay => fail closed, journal неизменен. **G8 — научная честность:** никаких `SEMANTICALLY_VERIFIED`, `DISCOVERED_LAW`, `UNIVERSAL_COVERAGE`, `EXPONENTIAL_SEARCH_SOLVED` по результатам этих инженерных тестов. Отдельно зафиксировать, где проверка детерминированная, а где статистическая и synthetic-only.
