# UDAV–NEXT–008 — новый закрытый тест жизненного цикла гипотез

**Не является правкой production.** Использовать исходный `007` исключительно для регрессии и RCA. Перед запуском зафиксировать SHA нового исследователя, набора конструкторов, контролей и независимого оценщика; создавать новые скрытые законы **после** этой фиксации, на новых seed и новых S/P-структурах.

## A. Явное состояние пространства моделей

Три независимые оси: `(main_status, shadow_status, adequacy_status)`.

- `MAIN_UNDERDETERMINED`, `MAIN_SINGLETON`, `MAIN_EMPTY`;
- `SHADOW_NOT_BUILT`, `SHADOW_MULTIPLE`, `SHADOW_SINGLETON`, `SHADOW_EMPTY`;
- `GRAMMAR_ADEQUACY_UNVERIFIED` сохраняется даже при singleton.

Операции: `construct_shadow(observations)` при первом `MAIN_SINGLETON` **или** первом `MAIN_EMPTY`; `update_shadow(observation)` при каждом следующем ответе; `active_bank` берётся из непустого основного банка, иначе из непустого теневого, но без автоматического присваивания `VERIFIED`. Если оба пусты — `MODEL_CLASS_INSUFFICIENT`, не подмена поддельным кандидатом. `SHADOW_SINGLETON` требует отдельного falsification-probe, а не принудительного утверждения истины.

## B. Факторное сравнение

Выполнить 2×2 `construct_shadow_on_empty` × `resume_shadow_after_main_empty` как причинные вмешательства, плюс два селектора `question_disagreement` и `seeded_uniform`, плюс sham с перестановкой оценок. Во всех плечах: один и тот же исходный набор CAT-запросов для primary frozen-pool сравнения, затем отдельная адаптивная проверка с зафиксированным seed и бюджетом. Измерять точные действия, количество локальных solve, число построенных шаблонов, CPU и невидимые альтернативы.

## C. Слепой oracle и трудные негативные случаи

Использовать новые seed и *новые* операции, не попавшие в подсмотренный набор `XOR3`:
- проверяемые семейства с малой поддержкой для функционального контроля;
- сложные правила с поддержкой 4–7 бит, композициями и зависимостью от порядка истории;
- закон вне текущих MAIN и SHADOW;
- две совместимые программы, которые не удаётся различить среди предложенных кандидатов, но можно различить вне пула.

Проверка истинности маленькой поддержки — полный перебор объединённой поддержки, а не проекция по 512 случайным адресам. Для больших поддержек — явно помеченный heldout, без претензии на универсальную эквивалентность. Истинный закон и контрольные адреса должны принадлежать отдельному модулю, недоступному генератору.

## D. Приёмочные критерии

1. Ни одной потери непустого теневого банка при переходе MAIN→EMPTY; проверяется сохранёнными контрпримерами.
2. Одинаковый ресурсный лимит для всех рук — не только число oracle queries, но и пределы локальных template checks и CAT-вычислений.
3. Обязательное сравнение на фиксированных пулах, затем на развивающихся траекториях; не смешивать эти два вывода.
4. Доказанная разница действий между arms на диагностическом транскрипте **до** holdout.
5. Статистическое превосходство хотя бы над seeded-uniform и sham по заранее объявленной *основной метрике* (например, доля корректных истинных альтернатив, найденных к q8/q16 без ложного `VERIFIED`), с поправкой на множественные сравнения.
6. Если сохраняется единственная правильная тень, но нет возможности проверить полноту языка, отдавать `UNIQUE_WITHIN_SHADOW_LANGUAGE`, `GRAMMAR_ADEQUACY_UNVERIFIED`.
7. Отдельный негативный отчёт для миров вне обеих грамматик и случаев отсутствия нужного адреса среди предложений.

В случае провала: не менять native ReversibleUDAV и не заявлять улучшение фундаментальной структуры поиска. Сначала выполнить RCA генератора/банка/селектора.
