# Semantic Bridge v0 — эксперимент SB-EXP01: формальные гипотезы, контрмодели, обязательства

**Дата:** 09.11.2026. **Статус:** действующие MCP-проверки + независимый локальный верификатор; без изменений production. **Проект MCP:** `semantic_bridge_exp01`.

## 1. Проверяемая гипотеза

Можно ли реализовать центральный механизм Semantic Bridge v0 уже существующими инструментами LivingMath, если **LLM формулирует интерпретации, а MCP только хранит типизированные конструкции, ищет контрмодели, проверяет модели и воспроизводит вычисления**?

Это эксперимент на *возможность механизма*, а не A/B-измерение роста точности перевода. Все альтернативы созданы клиентской LLM явно, H1/H3/H4 включены намеренно как ошибки/отрицательные контроли. Исходный текст синтетический. Gold labels серверу не подавались; однако контрольные конструкции заранее заданы автором эксперимента, поэтому ни «слепоты», ни доказанного исправления ошибки модели здесь нет.

## 2. Исходный текст и язык

> Каждый исследователь сообщил своему руководителю обо всех гипотезах, которые он проверил, но не сообщил о тех, которые только предполагал проверить.

UTF-8 source SHA-256: `2f27c8239b74438c5796715017e738aab3d0755e76c7eb1c4660412a205ad647`.

Сорта: `researcher`, `manager`, `hypothesis`. Предикаты:

- `S(m,r)` = `Supervises(manager,researcher)`;
- `C(r,h)` = `Checked(researcher,hypothesis)`;
- `P(r,h)` = `Planned(researcher,hypothesis)`;
- `R(r,m,h)` = `Reported(researcher,manager,hypothesis)`.

Везде ниже `∀rmh` значит `∀r:researcher ∀m:manager ∀h:hypothesis`. Эти области *не пусты* в явных моделях MCP. Связки `A⇒B` в передаваемом AST развёрнуты в `¬A∨B`; сервер FOL не имеет примитива импликации.

## 3. Пять гипотез, предложенных вне MCP

`H0` — содержательно правдоподобная трактовка «лишь планировал» как `P ∧ ¬C`:

\[
 H_0=\forall rmh\,[\neg S\lor((\neg C\lor R)\land(\neg P\lor C\lor\neg R))].
\]

`H1` — намеренно чрезмерно сильное запрещение отчётов о любой запланированной гипотезе, включая уже проверенную:

\[
 H_1=\forall rmh\,[\neg S\lor((\neg C\lor R)\land(\neg P\lor\neg R))].
\]

`H2` — тот же `H0`, но связанные переменные `r,m,h` переименованы в `u,v,t` при сохранении сортов и мест использования.

`H3` — намеренно ошибочное обращение импликации:

\[
 H_3=\forall rmh\,[\neg S\lor\neg R\lor C].
\]

Оно говорит «всё сообщённое проверено», а не «всё проверенное сообщено».

`H4` — неподдержанный оператор `future` в FOL AST; служит отрицательным контролем для выразительности.

### Фактический typecheck MCP

`H0,H1,H2,H3`: `TYPED` (17, 16, 17, 10 AST nodes соответственно); `H4`: `TYPE_REJECTED / INVALID_FORMULA_OPERATOR`. Это **типовая**, не смысловая проверка.

Все пять гипотез зарегистрированы одной командой `formal_interpret` с `candidate_provider.kind=external_llm`, `LLM_calls=0`, `semantic_alignment_status=PROPOSED`. Целиком исходный текст привязан по одному корректному UTF-8 span. Такая привязка обеспечивает сохранность источника, **но недостаточна для привязки отдельных узлов AST к словам**; это долг последующей архитектуры.

## 4. Контрмодели, полученные действующим MCP

`formal_contrast` на H0/H1 за 16 проверенных моделей нашёл:

- один исследователь `r0`, один руководитель `m0`, одна гипотеза `h0`;
- `S(m0,r0)=C(r0,h0)=P(r0,h0)=R(r0,m0,h0)=TRUE`;
- `H0=TRUE`, `H1=FALSE`;
- `FINITE_COUNTERMODEL`, модель SHA `4d79df34ff9ec594c55c73972df0ac8d6442286c162174f92bb820ab79a729e7`.

`formal_contrast` H0/H3 нашёл другой сценарий:

- `S=TRUE`, `C=P=FALSE`, `R=TRUE`;
- `H0=TRUE`, `H3=FALSE`;
- `FINITE_COUNTERMODEL`, модель SHA `90dbb7763e2da66fc8b8269f4257773f1c45a2cfdbcb8b1d68d51d248fd5655f`.

В противоположном направлении явная модель `S=C=TRUE, P=R=FALSE` проверена через `formal_model_check`:

- `H0=FALSE`, `H3=TRUE`.

Поэтому `H0` и `H3` **несравнимы**, причём это доказано двумя предъявленными конечными контрмоделями (здесь конечность достаточна для опровержения обоих глобальных следований).

`formal_contrast` H0/H2: `UNKNOWN_BOUND`, `models_checked=16`, `reason=RELATION_CELL_BOUND`. Два элемента каждого сорта потребовали бы 20 ячеек бинарных/тернарных отношений, а текущий enumerator останавливается при `>16` ячейках. `UNKNOWN_BOUND` корректен, но бессмысленно дорог для обычного alpha-переименования.

**Независимая проверка:** `verify.py` сравнивает canonical binder-normalized AST H0 и H2 и доказывает их α-эквивалентность синтаксически. Он также перебирает все `2^4=16` локальных булевых случаев `S,C,P,R` и доказывает для одного фиксированного `(r,m,h)` тождество `body(H1)⇒body(H0)`. Универсальное замыкание даёт `H1⇒H0` на любых структурах. Глобальная эквивалентность H0/H2 не является выводом `formal_contrast`; это отдельно полученный синтаксический результат.

## 5. Матрица проверенных ситуаций

| Сценарий (все сорта по одному элементу) | H0 | H1 | H2 | H3 |
|---|---|---|---|---|
| M1: S,C,P,R=true | TRUE | FALSE | TRUE | TRUE |
| M2: S,R=true, C=P=false | TRUE | TRUE | TRUE | FALSE |
| M3: S,C=true, P=R=false | FALSE | FALSE | FALSE | TRUE |
| M4: S=C=P=R=false | TRUE | TRUE | TRUE | TRUE |
| M5: тот же M1, но `world=open` | UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

Все двадцать значений проверены отдельными `formal_model_check`. `verify.py` независимо вычисляет таблицу по frozen AST. Сервер не утверждает, что TRUE означает верный перевод исходного текста.

## 6. Обнаруженная семантическая недостаточность H0

`H0` истинно в M4 без руководителя, потому что импликация `S(m,r)⇒...` истинна при `¬S` для любого `m`. Между тем словосочетание «своему руководителю» **может** содержать пресуппозицию существования руководителя, возможно единственного. Это **не** автоматически доказанное языковое следствие, а кандидат контекстного обязательства.

LLM предложила отдельную предпосылку:

\[
 A_{\mathrm{exist}}=\forall r\,\exists m\,S(m,r).
\]

Эта предпосылка сохранена MCP отдельно от исходного `H0` в новой регистрации. Действующий `formal_model_check` выдаёт:

- на M1: `formula=TRUE`, `assumption=TRUE`;
- на M4: `formula=TRUE`, `assumption=FALSE`.

Так формула, её предпосылки и смысловая интерпретация **не смешиваются**. Наличие отдельного поля `assumption_results` позволяет сделать рабочий прототип без изменения native kernel. Но в нынешнем интерфейсе нет автоматического поиска пресуппозиций: их предложила LLM при чтении контрмодели.

Возможная единственность руководителя, значение «только предполагал», время проверки и анафора «он» остаются отдельными открытыми обязательствами.

## 7. Проверка воспроизводимости

`formal_replay` вернул `REPLAY_MATCH` для трёх ранее созданных runs: `formal_interpret`, `formal_contrast(H0,H1)`, `formal_model_check(M1,H1)`.

Это проверка вычислительных пакетов, а не семантическая экспертиза авторского намерения.

## 8. RCA и вывод

**Теоретическая часть работает:** модели-конкуренты создаёт внешняя LLM; MCP даёт проверенные контрмодели; LLM может выявлять ошибки более сильных/неправильно направленных утверждений, не доверяя серверу авторский смысл.

**Что уже есть в сервере:** `formal_interpret`, `formal_contrast`, `formal_model_check`, `formal_store`, `formal_replay`, provenance и assumptions. Для этого эксперимента `udav_symbolic_explore` не вызывался; данный шаг изолирует именно семантический контраст как недостающий вычислительный механизм.

**Что не работает из коробки:**

1. Нет точного α-эквивалентностного checker'а в этом пайплайне; FOL countermodel engine пытается без нужды перебирать модели.
2. Нет составного `ContextualHypothesis` с typed AST-node → token-span links и обязательствами.
3. Нет структурированных, проверенных proof/entailment edges с корректным `GLOBAL` vs `FINITE` статусом.
4. Нет автоматизированной сводки `formula TRUE but assumption FALSE` как несовместимости сценария с гипотезой **под её явными предпосылками**.
5. Нет `LANGUAGE_INSUFFICIENT` как first-class результата для операторов вне языка; сейчас лишь `TYPE_REJECTED`.
6. Нет интерфейса от нового `udav_core` к семантическому графу; напрямую подключать его к NL смыслу не следует до определения семантических инвариантов.

**Наиболее важное ограничение эксперимента:** H1/H3 намеренно сконструированы как ошибочные кандидаты. Исправление неподходящей формулы на основании контрмодели *логически возможно* и демонстрируется, но причинная прибавка к качеству реальной малой или большой модели не измерялась. Для измерения нужна фиксация первоначальной ошибки реальной модели, слепые контрольные ветки с настоящей/ложной контрмоделью, независимое оценивание смысла и несколько текстов.

## 9. Минимальная версия слоя после эксперимента

Рекомендуемая реализация **как композиция уже существующих tools**, без изменения алгоритмов UDAV, NOPS, CAD и Белой звезды:

- LLM создаёт `ContextualHypothesis` + `assumptions/obligations` + typed spans.
- MCP проверяет α-эквивалентность локальным checker'ом, а затем только отличающиеся формулы пропускает в `formal_contrast`.
- MCP выполняет `formal_model_check` для контрмоделей и предложенных LLM контекстных сценариев.
- В ответе всегда отдельно возвращаются `formula_truth`, `assumptions_truth`, `relation_scope`, `source_alignment_status=PROPOSED` и unresolved obligations.
- LLM делает семантическое заключение и может вернуть уточнённый кандидат. Никакой автоматической метки `SEMANTICALLY_VERIFIED`.

Контроль после P0: α-пара должна завершаться доказанной α-эквивалентностью **без** модельного перебора; несравнимые пары — выдавать оба направления с проверенными моделями; недостаточные выразительные средства — возвращать отдельный статус, а не молчаливое ослабление текста.
