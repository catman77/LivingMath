# LM–SUTI–SEMANTIC–BRIDGE–001 — пакет для Codex

Вложено:

- `TZ_LM_SUTI_SEMANTIC_BRIDGE_V02.md` — основное техническое задание, критерии и границы.
- `PROMPT_CODEX_SEMANTIC_BRIDGE_001.md` — непосредственная инструкция кодовому агенту.
- `ACCEPTANCE_MATRIX.md` — 36 проверок positive/negative, release safeguards.
- `SEMANTIC_RECORD_EXAMPLE.json` — **схематический пример нового формата**, не зарегистрированная схема текущего MCP и не научный результат.
- `MANIFEST.sha256` — контрольные суммы остальных файлов.

Кодовый агент должен начать с проверки **реальных** текущих contracts и репозитория. Создаваемая схема является добавочной; пример не имеет права подменять спецификацию frozen checker.

База v0.1: `release-v01-20261104T181130Z`, verifier `a035303149c1307126ff26e4bf60725daf3b104598be8a04a958e14388a61f08`.

Проверка содержимого после распаковки:

```bash
sha256sum -c MANIFEST.sha256
```

Промпт из файла можно отправить Codex вместе со всем архивом. Не публиковать корпус с неразрешёнными правами, а финальный R3 объявлять только после двух внешних человеческих replay-отчётов.

`POETRY_QA_FIXTURES.json` содержит копии *рабочих* транскрипций, использованных в исходном MCP-пилоте. Их `raw_text_sha256` относится к точному UTF-8 тексту со строками, соединёнными `\n`, и **отличается** от SHA предыдущего JSON контейнера; это разные объекты. До model inference Codex обязан проверить редакцию и зафиксировать новые настоящие `SourceEditionSnapshot` без тихих текстовых исправлений. `build_fixtures.py` — детерминированная stdlib-утилита пересборки этих тестовых данных, не runtime-патч продукта.
