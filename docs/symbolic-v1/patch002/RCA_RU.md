# RCA — bounded local saturation PATCH002

## Воспроизведённая причина

Сохранённый run61c5af7a... и исходный source1855b60a... реально выгружены через MCP
и пересчитаны immutable v0.4.1 worker: digest b134c3684e546b3ffa60ebf049f8393db9fc17beab45f118ef3007cfe1d529d8.
18 состояний,5 шагов,20 proposals; это не симуляция старого поведения.

В search.py PATCH001 отсутствие новых outputs очищало локальный выбор, оставляя
current равным пустому слову. SPLIT(position=0) и REVERSE возвращали пустое,
CONCAT с сохранёнными record roots возвращал уже известные слова. Clock a=33,b=87
повторялся. На третьем no-growth шаге локальный сертификат завершал весь search,
хотя сохранённые узлы имели64 непроверенные пары node/operator. RENAME не был
предложен в этом локальном цикле. Ограничение принадлежит controller/frontier,
а не корпусу или точной алгебре.

## Минимальное исправление

Сохраняется весь исходный локальный алгоритм. Только после его no-growth события
выбирается минимальный digest(seed,operator,node_id) среди untried **сохранённых**
пар. Следующий обычный шаг тратит обычный candidate slot и прежний clock на
proposal. В данном случае выбран SOURCE_RECORD второй строки и RENAME; новый
проверяемый узел19e01abe... даёт непосредственное свидетельство выхода из тупика.
В том же request и бюджете поиск доходит до383 узлов/99 шагов/MAX_NODES.

Это bounded scheduler, не полный enumerator слов/деревьев/программ или новый
математический оператор. Равенства, SP-involution, alpha, источники и grammar
не менялись. ACTUAL_LOCAL_EXHAUSTION удостоверяет только охват текущих пар с
одной вариацией аргументов, global_exhaustion_proved=false.

## Контроли и границы

Первые5 trace entries и source_map совпадают с golden production; полный
train-only grammar/heldout JSON совпадает с исходным. Исходный Малларме не
получает fallback и сохраняет640 узлов/141 шаг; обращённый получает два bounded
перехода и466 узлов/160 шагов/MAX_STEPS. У каждой пары before/after request и
бюджеты одинаковые; другие Nostradamus режимы из архива не использованы как
причинный контроль. Никакого вывода о новом смысле из числа узлов нет.

Первый red test выявил отсутствие новых diagnostic fields, первоначальный
прогон19 PASS/1 FAIL — старое ожидание терминального NO_NOVEL_CANDIDATES в тесте
PATCH001. Оно намеренно заменено проверкой LOCAL_STAGNATION certificate плюс
bounded fallback: старое завершение и было предметом ТЗ. Исходные логи сохранены;
окончательные272 source/wheel и248 production checks PASS. Нулевой бюджет не
порождает фиктивный saturation certificate. Ранее не записанная budget-blocked
попытка теперь отражена в trace и per-operator accounting.

При CPU/RAM/wall ограничении WORKER_LIMIT остаётся настоящим отказом supervisor;
частичные несохранённые наблюдения не выдумываются. Никаких ресурсов не добавлено.
Все исторические модели/артефакты неизменны и пересчитываются соответствующими
immutable профилями. Неизвестный kernel binding не исполняется из ZIP.

Незакрытых инженерных FAIL в данной конечной матрице нет. Единственность грамматики,
полнота алгебры, филологическая интерпретация, full pentest/длительная нагрузка и
hosted CI этим патчем не доказаны и не объявлены прошедшими.
