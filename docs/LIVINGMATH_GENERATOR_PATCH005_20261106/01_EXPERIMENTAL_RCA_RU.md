# RCA: один короткий положительный пример ломает генератор композиционных гипотез

## Объект и условия

Проверен живой MCP `v0.4.6`, deployment `recursive004-20261106T060730Z`; проект `whitestar_dialog_test`. Все запросы запущены с **новыми** `request_key`, а прежние контрольные серии использованы только как исторические ориентиры. Датасеты: буквальные S/P-слова, `training labels` только в `train_ref`; `predict_ref` без меток; `enabled_builtins=[]`; `promotion_policy.mode=compositional_ast`, `candidate_sources=["derivation_trace"]`; `seed=137`; `max_ast_nodes=32`, `max_ast_depth=8`, `max_recursion_steps=8`, `max_tokens=8`, `max_train_witnesses=256`, `max_runtime_ms=4000`; все требования `source-boundaries`, независимой проверки и запрета исполнения включены.

## Более широкие подтверждения

- Train Σ⁴ (16): скомпонован `iterate_on_inner_fragment`, 64/64 для Σ⁶ и 256/256 для Σ⁸.
- Train Σ²∪Σ⁴ (20): новый синтезатор `NO_TRAIN_COMPATIBLE_TYPED_COMPOSITION`. Наблюдаемый сервисный run `2266e46365d2f2b3d626d65b8ee80fd849803d53801b62d5f0123423ae35b7ee`.
- Train Σ¹∪Σ²∪Σ³∪Σ⁴ (30): аналогичный отказ, run `5d9c362cbbb17d77ddd17de9f2226397f0f7b0e87cd5b1bfb2fa250fa3e19249`.
- Train Σ¹∪Σ³ (10): выбран недостаточный `endpoint_equal`, на длине 7 результат 80/128, включая 48 FP, run `f415d41cdf0a87651321ec98a1adaf3905186637daafd4b099026104ad03a5f4`.
- Train Σ¹∪Σ³∪Σ⁵ (42), Σ²∪Σ⁴∪Σ⁶ (84): отсутствует совместимый композиционный кандидат; при >64 train контекстный путь имеет отдельный лимит `FINITE_SHORT_WORD_SCOPE_REQUIRED` (но проблема сохраняется и при 17, 20, 30, 42 примерах).
- Старый `symbolic_v1` на смешанном train также выбирает ограниченные признаки, что локализует слабость на уровне общего пространства/генерации кандидатов, а не только нового верификатора.
- COPY с train Σ²∪Σ⁴∪часть Σ⁶ (52) успешно переносится на Σ⁸: 256/256. Поэтому утверждение «все смешанные длины не поддерживаются» опровергнуто.

## Математический контроль

Независимый finite-oracle из `reference/pal_copy_oracle.py` вычисляет:

P(ε)=P(a)=true;
P(a u b)=(a=b)∧P(u).

Он даёт **0 противоречий** на каждом train B, B+SS, B+PP, B+SP, B+PS, Σ²∪Σ⁴, Σ¹…Σ⁴, Σ¹∪Σ³∪Σ⁵. Следовательно, совместимая грамматика существует, а генератор её не предложил / не сохранил. Для этого вывода достаточно независимой конечной проверки; универсальность выбранной гипотезы **из одних данных** не следует.

## Аналитическое резюме

Решать нужно в генераторе/ранжировании типизированных композиционных AST и учёте пустого/односимвольного base case. Изменения независимого checker только если обнаружена *реальная* ошибка после предъявления корректного AST (сейчас такого свидетельства нет). Переписывание Белой звезды, SP-комплекса, парсера литературы не обосновано.
